My Inno Setup Extensions: how to


Welcome to the My Inno Setup Extensions advanced Pascal scripting 'how to' page.

The scripting engine currently used by My Inno Setup Extensions is Innerfuse Pascal Script by Carlo Kok from Innerfuse. Like My Inno Setup Extensions, Innerfuse Pascal Script is freely available and comes with source. See http://www.weyert.com/ifs for more information.

The scripting support adds about 25 kb to the size of an installer.

(Updated December 20 2000)

General

The advanced Pascal scripting feature is completely optional, but if used it adds lots of new possibilities. Some examples:
  • Support for aborting setup under custom conditions.
  • Support for extracting and running or calling files from the Pascal script before, during or after the installation.
  • Support for scripted constants that can do anything the normal constants, the read-from-registry, read-from-ini and read-from-commandline constants can do + more.
  • Support for runtime removal of types, components and/or tasks under custom conditions
  • Support for conditional installation of [Files], [Registry], [Run] etc. entries based on custom conditions.
  • Lots of support functions to do from the Pascal script just about everything Inno Setup itself does/can do + more.

The Pascal script is interpreted at run time, which means that syntax error messages and similar errors will be displayed while actually running Setup and not while compiling your setup.exe file.

A sample Pascal script.

One new directive is used to specify the Pascal script file that has to be used: 

[Setup]

The following is a list of new directives:

CodeFile
 Default value: none
Description:
Name of the My Inno Setup Extension/Innerfuse Pascal Script compatible Pascal script file.

 
'Event' functions

The Pascal script file can contain several 'event' functions which are called at appropiate times. These are:
  • function InitializeSetup(): Boolean;
    return False to abort Setup
  • procedure DeInitializeSetup();
  • procedure CurStepChanged(CurStep: Integer);
  • function NextButtonClick(CurPage: Integer): Boolean;
    return False to surpress the click on the Next button
  • function BackButtonClick(CurPage: Integer): Boolean;
    return False to surpress the click on the Back button
    function SkipCurPage(CurPage: Integer): Boolean;
  • return True to skip the CurPage page
    procedure CurPageChanged(CurPage: Integer);

Remarks:

-None of these functions are required.
-See the bottom of this page for possible values of the CurStep and CurPage parameters.
-SkipCurPage isn't called if Setup already determined that the page should be skipped.
-SkipCurPage isn't called for the Welcome (wpWelcome) and the Installing (wpInstalling) pages.

 
'Check' functions

The Pascal script file can contain several 'check' functions which are called during the installation and determine whether entries in sections like [Files], [Registry], [Run], etc. should be processed or not.

[Types], [Components], [Tasks], [Dirs], [Files], [Icons], [INI], [InstallDelete], [Registry], [Run], [UninstallDelete], [UninstallRun]

The following is a list of new parameters for entries in the above sections: 

Check:
The name of the function in the Pascal script file that determines whether an entry has to be processed or not.

Here is a example, for the .iss file:

[Files]
Source: MyProg.exe; DestDir: {app}; Check: MyProgCheck

and for the Pascal script file:

function MyProgCheck(): Boolean;
begin
  Result := MsgBox('Do you want to install MyProg.exe?', mbConfirmation, MB_YESNO) = idYes;
end;

Remarks: 

-The 'check' function has to have the same prototype as in the example above: no parameters and a Boolean return value. If the 'check' function returns True, the entry is processed otherwise it's skipped.
-If several entries have the same Check parameter, Setup will call the script function several times. If your function performs the same code each time, you can optimize it by performing to code only once and 'caching' the result in a global variable.
-An entry without a Check parameter is always installed, unless it's Components and/or Tasks parameter says it shouldn't.
-The 'check' function isn't called if Setup already determined from the entry's Components and/or Tasks parameter that it shouldn't be processed.

 
'Constant' functions

The Pascal script file can contain several 'constant' functions which are called when Setup wants to know the value of a 'scripted constant'. These constants work similar to the read-from-registry and similar constants:

{code:functionname|defaultvalue}

An example of the use of such a constant, for the .iss file:

DefaultDirName={code:myconst}\MyProg

and in the Pascal script file:

function MyConst(Default: String): String;
begin
  Result := ChangeDirConst('{pf}');
end;

Remarks:

-The 'constant' function has to have the same prototype as in the example above: 1 parameter containing the Default value (as possibly specified in the .iss file) and a String return value. The return string of the function is used as the value for the constant.
