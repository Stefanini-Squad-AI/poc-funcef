🔄 Transações e commit/rollback

O motor dFolhaPrevia.pas gerencia transações via dtmBaseDados.dbBaseDados (componente de conexão Oracle). Padrão: processa um bloco → Commit → StartTransaction (nova transação para o próximo bloco), evitando transações longas. Pontos confirmados:

  • IncluiPrevia: Commit (:4138) + StartTransaction (:4139)
  • EfetivaRubricas: Commit (:6468) + StartTransaction (:6471)
  • CaluloIRRF: StartTransaction (:15679) → Commit (:15697); (:15880→15888); (:15974→15997); (:16016→16025)
  • ProcessaPrevia: StartTransaction (:24890, :25386) → Commit (:25383, :25405)

Rollback: não identificado explicitamente no motor — em caso de exceção, a transação corrente permanece aberta (commit apenas em sucesso). PENDENTE — estratégia de rollback por erro não confirmada. Evidência: FOLHA/Fontes/dFolhaPrevia.pas — COMPROVADO (commit/start); rollback PENDENTE.

🗄️ Views, sequences e SQL characteristics
  • Sequences/DUAL: Oracle — geração de IDs via sequence e DUAL (confirmado em arquitetura).
  • SQL inline: 298 ocorrências de SQL (INSERT/UPDATE/DELETE/SELECT) em dFolhaPrevia.pas, montadas por concatenação de strings (ssql).
  • Joins/filtros/ordenação: presentes nas consultas de lookups (DLookFolha, DFolha) e relatórios (dRel*). COMPROVADO (presença); mapeamento exaustivo de cada SQL PENDENTE por volume.
  • Stored procedures: Exec_SP_ExcessoDebito (fFolhaNormalEfet.pas:8158, festornafolha.pas:1801) — SP de excesso de débito. COMPROVADO
  • Views: nenhuma view identificada nos DBObjects (acesso direto a tabelas). PENDENTE — views externas não confirmadas.
