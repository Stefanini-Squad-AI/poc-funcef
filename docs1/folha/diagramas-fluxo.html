📖 Para o leigo — O passo a passo dos processos (enriquecido — PFC-42)

Esta aba mostra o "passo a passo" dos principais processos do módulo FOLHA, como uma receita ilustrada. Cada fluxo é um diagrama que mostra, em ordem, o que o sistema faz desde o início até o fim do processo.

Os fluxos documentados (todos com rastreabilidade ao código):

  • PF-01 — Preparo da Folha: seleciona patrocinadoras, planos e benefícios → inicializa o processo → para cada benefício, grava histórico e calcula pro-rata → guarda na tabela de histórico.
  • PF-02 — Prévia (Cálculo): o motor percorre cada recebedor → processa rubricas de provento → aplica regras → classifica em bases → insere na prévia → faz rateio e REINF → grava na base de pagamento.
  • PF-03 — Efetivação: valida lote/conta/parâmetros → executa ETL → gera arquivo CNAB 150 ou 240 → atualiza base de pagamento → gera arquivo SIACC → grava histórico definitivo.
  • PF-04 — Estorno: verifica status → desfaz rubrica individual → gera alterador → gera CAP/CAR → grava motivo → processa compensação.
  • PF-05 — Remessa Bancária: abre fita de crédito → gera arquivo CNAB (150 ou 240 conforme leiaute) → seta documento, favorecido e registros → grava na tabela de arquivos de pagamento.
  • PF-08 — IRRF: determina bases → atualiza flag de isento → verifica compensação → decide entre IR normal ou regressivo → lança IR compensado → grava na bitributação.

Cada caixa no diagrama é uma rotina do código (com o nome e a linha onde está). As setas mostram a ordem de execução. Os cilindros representam tabelas do banco que são lidas ou gravadas.

💼 Para o analista de negócios — Gargalos e pontos de decisão (enriquecido — PFC-42)

Pontos de decisão de negócio (onde o sistema escolhe um caminho com impacto financeiro):

  • PF-02: classificação de rubrica em base — decide se a rubrica incide em IR, INSS, FGTS etc. Classificação errada gera cálculo tributário incorreto.
  • PF-05: leiaute CNAB 150 vs 240 — a escolha do leiaute depende do banco/convênio. Usar o leiaute errado faz o banco rejeitar a remessa.
  • PF-08: IR normal vs regressivo — a opção tributária do beneficiário define se o IR é calculado pela tabela progressiva ou pela regressiva. Erro aqui gera imposto errado e possível passivo tributário.

Gargalos potenciais (pontos onde o volume pode impactar o tempo de processamento):

  • PF-02 (Prévia) — processa beneficiário por beneficiário, rubrica por rubrica. Para grandes volumes (50 mil+ beneficiários), o cálculo pode levar horas. O commit parcial a cada N registros ajuda, mas uma falha no meio exige reprocessamento.
  • PF-03 (Efetivação) — a geração do CNAB e do SIACC é sequencial. Se um arquivo falha, o outro pode já ter sido gerado — exige tratamento cuidadoso de retomada.

Dependências entre fluxos: PF-03 (efetivação) só roda após PF-02 (prévia). PF-04 (estorno) só roda após PF-03. PF-05 (remessa) depende de PF-03. Isso significa que um erro em um fluxo inicial bloqueia os subsequentes — a ordem de execução é rígida e deve ser respeitada no planejamento operacional.
