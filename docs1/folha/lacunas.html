📖 Para o leigo — O que ainda não sabemos sobre o sistema (enriquecido — PFC-42)

Esta aba é como uma lista de dúvidas sobre o módulo FOLHA. Mesmo após a análise do código, há coisas que não foi possível confirmar — seja porque o código é muito grande para analisar linha a linha, seja porque depende de outros sistemas que não foram inspecionados.

Tipos de lacuna (dúvidas) encontradas:

  • Artefatos pendentes — arquivos que existem no repositório mas cuja função exata não foi confirmada. Ex.: o motor de cálculo tem 30.856 linhas; as rotinas-chave foram documentadas, mas o detalhe de todas as 7.088 declarações não — é trabalho demais para fazer à mão.
  • Dependências externas não analisadas — o FOLHA conversa com outros módulos (CONTRIBUIÇÃO, BENEFICIOPREV, IRRF, PROCJUD) e com o banco Oracle. A implementação interna desses interlocutores não foi inspecionada — sabemos que o FOLHA os chama, mas não exatamente o que eles fazem por dentro.
  • Itens não comprovados — comportamentos que parecem fazer sentido (inferidos) mas não foram verificados no código. Ex.: alguns blocos de tratamento de erro têm o except vazio — pode ser intencional ou pode ser um bug.

Cada lacuna é marcada com um selo de evidência: COMPROVADO (confirmado no código), INFERIDO (plausível mas não confirmado) ou PENDENTE (depende de validação adicional). Isso ajuda a saber o quanto confiar em cada informação.

💼 Para o analista de negócios — Riscos de negócio por informação faltante (enriquecido — PFC-42)

Riscos que exigem atenção (lacunas com potencial de impacto de negócio):

  • Stored procedure de excesso de débito (Exec_SP_ExcessoDebito, festornafolha.pas:1801) — uma procedure do banco é executada no estorno, mas seu nome e conteúdo não foram extraídos. Risco: o estorno pode ter comportamentos não documentados que afetam o saldo do beneficiário.
  • try/except silenciado — erros capturados e ignorados podem mascarar falhas de negócio (ex.: gravação que falha silenciosamente). Risco: dados inconsistentes sem alerta operacional.
  • Dependências externas (CONTRIBUIÇÃO, BENEFICIOPREV, IRRF) — o FOLHA depende desses módulos para calcular a folha, mas suas implementações internas não foram inspecionadas. Risco: mudanças nesses módulos podem afetar o FOLHA sem que a equipe do FOLHA saiba.
  • MongoDB (carga de contra-cheque) — a integração com MongoDB é inferida, não confirmada. Risco: se a carga falhar, o portal do participante pode ficar desatualizado sem alerta.

Recomendações para o analista:

  • Priorizar a verificação dos except vazios no motor de cálculo — são os pontos onde falhas silenciosas podem causar maior impacto financeiro.
  • Documentar a stored procedure de excesso de débito com o DBA, pois ela afeta o estorno (processo de correção de folha).
  • Estabelecer um acordo de mudança (change management) com as equipes de CONTRIBUIÇÃO, BENEFICIOPREV e IRRF, pois alterações nesses módulos podem impactar o cálculo da folha.
