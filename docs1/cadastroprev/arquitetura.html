O que esta aba mostra: como o programa Cadastro Previdenciário é organizado por dentro — as camadas de código, os padrões de acesso ao banco de dados e como as telas se conectam com o framework CM.

Por que isso importa: entender a arquitetura ajuda a localizar onde está cada regra de negócio e o que precisa ser testado ao mudar algo. O módulo segue o padrão do framework CM (telas de cadastro, DataModules, DBObjects), mas tem particularidades: o menu de eventos é dinâmico e o motor de saldamento é uma unit separada de 8.861 linhas.

🏗️ Arquitetura do Módulo

O módulo CADASTROPREV é uma aplicação Delphi 5 MDI (Multiple Document Interface) que herda do framework CM. A tela principal FPrincipal (classe TfrmPrincipal, herda de TfrmCMPrincipal) é o container MDI pai com o menu principal. O menu "Eventos" é construído dinamicamente em MontaMenu (FPrincipal.pas:701) consultando a tabela EVENTOGERADOR filtrada por FLGINTERNO e IDFUNDACAO COMPROVADO.

Application.Title = 'Cadastro Previdenciário' (CadastroPrev.dpr:143). IdModulo = 452 (FPrincipal.pas:2110). Versão = 3.00.07.

O acesso a dados usa o padrão TCmDbObject (DBObjects formais) e TwwQuery (SQL inline nos forms). Não há componentes de conexão a servidor remoto (TDCOMConnection/TSocketConnection) nos .dfm — o acesso é local, via DBaseDados (datamodule de conexão do CM) INFERIDO.

👔 Para o analista de negócios

  • A separação entre "forms com SQL inline" e "DBObjects formais" é importante: apenas 3 tabelas têm DBObject (EVOLFUNCPREV, HISTRUBSAL, RESERVAPART). As demais 54 tabelas são acessadas via SQL escrito diretamente nos forms, o que dificulta rastreabilidade e manutenção.
  • O motor de saldamento (USaldamento.pas) é uma unit sem form — puramente de domínio. As 5 classes de saldamento (Ativo, Aposentado, Pensionista, Assistido, Associado) implementam o padrão Strategy.

⚙️ Entry point e inicialização

O CadastroPrev.dpr (305 linhas) inicializa a aplicação na seguinte ordem COMPROVADO:

  1. Cria e exibe frmCMEntrada (splash screen do CM)
  2. Application.Initialize; Application.Title := 'Cadastro Previdenciário'
  3. Auto-cria ~30 forms/datamodules (frmPrincipal, dtmReports, dtmRelatAdmPrev, frmEventoReclusao, etc.)
  4. Libera frmCMEntrada; Application.Run

Na seção initialization (FPrincipal.pas:2773-2779): Sistema.NomeModulo := 'CadastroPrev', Sistema.IdModulo := 452, Sistema.Versao := '3.00.07', IntegraBack := TIntegraBack.Create(True, True, True) (integração com contabilidade + financeiro + empréstimo).

👔 Para o analista de negócios — síntese (PFC-73)

A arquitetura segue o padrão CM: forms de cadastro herdam de classes base do framework, DBObjects encapsulam tabelas, e CtrlObjects orquestram a lógica. A particularidade do CADASTROPREV é o menu dinâmico de eventos (23 tipos) e o motor de saldamento como unit separada.

Áreas de risco na modernização:

  • SQL inline nos forms (54 tabelas sem DBObject) — difícil de migrar para um ORM moderno.
  • Dependência massiva de units compartilhadas (UAdmPrev em 23 files, UBeneficio em 14, URegra em 13) — qualquer mudança nestas units afeta o módulo.
  • O motor de saldamento (8.861 linhas) é o maior bloco de lógica e não tem testes automatizados.
