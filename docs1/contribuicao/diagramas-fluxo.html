📖 Para o leigo — O passo a passo dos processos (enriquecido — PFC-42)

Esta aba mostra o "passo a passo" dos principais processos do módulo CONTRIBUIÇÃO, como uma receita ilustrada. Cada fluxo é um diagrama que mostra, em ordem, o que o sistema faz do início ao fim.

Os fluxos documentados (todos com rastreabilidade ao código):

  • PF-01 — Preparo e Envio: seleciona patrocinadora × plano × situação → para cada combinação, gera histórico de contribuições → envia para cobrança (folha ou banco, conforme FLGDESCFOLHA) → marca como enviada.
  • PF-02 — Recebimento multi-canal: seleciona contribuições enviadas → para cada uma, compara valor esperado com recebido → marca situação (recebida, divergente, pendente) → cobra a patrocinadora/participante se divergente.
  • PF-03 — Alimentação de reservas: seleciona reservas por plano → aplica regra numérica ou itera índices de correção → insere movimento de reserva → atualiza saldo.
  • PF-05 — Bitributação / IR regressivo: exclui histórico anterior → soma contribuições de 1989-1995 corrigidas (moeda 557) → calcula saldo de 2007/12 iterando IPCA-E → grava bitributação.
  • PF-06 — Portabilidade e benefício saldado/FAB: insere contribuição portada → insere histórico → chama procedure Oracle para atualizar saldo do benefício saldado.
  • PF-07 — Provisão para perdas: seleciona contribuições atrasadas → calcula provisão (valor esperado × percentual da faixa de dias) → contabiliza a provisão.
  • PF-08 — Tratamento de divergências: exibe divergências sintéticas → cobra próximo mês ou trata via banco → valida situação × modo → insere histórico.

Cada caixa no diagrama é uma rotina do código (com nome e linha). As setas mostram a ordem de execução. Os cilindros representam tabelas do banco lidas ou gravadas.

💼 Para o analista de negócios — Gargalos e pontos de decisão (enriquecido — PFC-42)

Pontos de decisão de negócio (onde o sistema escolhe um caminho com impacto financeiro):

  • PF-01: FLGDESCFOLHA=1? — decide se a contribuição é descontada em folha (TMPDESC) ou cobrada via banco (CAP/CAR). A escolha errada faz a contribuição não ser descontada ou ser cobrada em duplicidade.
  • PF-02: Esperado = Recebido? — decide se a contribuição é marcada como recebida (situação 2) ou divergente (situação 3). Divergências não tratadas acumulam inadimplência.
  • PF-05: moeda 557 (IPCA-E) — o índice de correção das contribuições de 1989-1995. Erro de índice gera saldo tributário errado.

Gargalos potenciais (pontos onde o volume pode impactar o tempo):

  • PF-01 (Preparo e Envio) — processa patrocinadora × plano × situação × participante. Para grandes volumes, o cálculo pode levar horas. O commit parcial a cada 800 registros ajuda, mas uma falha no meio exige reprocessamento.
  • PF-05 (Bitributação) — itera mês a mês a partir de 2008/01 com IPCA-E. Para participantes com longa história, o número de iterações é alto.

Dependências entre fluxos: PF-02 (recebimento) só roda após PF-01 (envio). PF-03 (reservas) depende de PF-02. PF-07 (provisão) depende de PF-02 (apenas contribuições recebidas/divergentes). Uma falha em um fluxo inicial bloqueia os subsequentes — a ordem de execução é rígida.
