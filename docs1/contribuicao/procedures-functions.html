💡 Em linguagem simples (enriquecido — PFC-42)

O que esta aba mostra: as principais “receitas” do módulo — as rotinas de código que fazem o trabalho pesado (calcular, enviar, receber, desfazer). Para cada uma: onde está, o que recebe, os passos e o que grava no banco de dados.

Por que isso importa: é aqui que as regras de negócio ganham forma concreta. Quando alguém pergunta “o que exatamente acontece quando clico em Enviar?”, a resposta está nestas rotinas.

Como ler esta página: cada bloco tem o nome da rotina e o arquivo:linha. “Parâmetros” são os ingredientes que a rotina recebe; “Processamento” é o modo de preparo; “Efeitos BD” é o que fica gravado no banco (INSERT = incluir, UPDATE = alterar, DELETE = apagar). Depois de cada grupo, “💡 Em outras palavras” resume o que a rotina significa para o negócio.

Termos usados nesta página — explicados de forma simples:

Termo técnicoEm linguagem simplesFonte

⚙️ FPreparaEnvia.pas — Preparo e Envio
PreparaContribuicao — FPreparaEnvia.pas:3724-4436

Propósito: Núcleo do preparo. Para cada patrocinadora×plano×situação, calcula e grava no histórico todas as contribuições devidas.

Parâmetros: nenhum → boolean (sucesso)

Processamento:

  1. SELECT DISTINCT patrocinadora×plano×situação de PLANPREVPATRO/PLANPREV/PESSOA/SITPART/PATRO WHERE FLGINTERNO<>'PT' (3751-3766)
  2. Para cada combinação: verifica PARAMSAL13 (cobra 13º?), verifica preparo do mês anterior (3883-3903)
  3. Sincronismo: VerificaFechamento → ProximoMesAberto (3928-3953)
  4. SELECT DISTINCT contribuições de CONTRIBUICAO/CONTPREV/CONTPLANPATRO WHERE FLGINTERNO=situação ORDER BY ORDEMCALCULO (3986-4024)
  5. Para cada contribuição: PreparaQry (abre participantes) → loop GeraHistorico por participante (4105-4183)
  6. Commit parcial a cada 800 registros (ictMaxCommit) (4173-4180)
  7. EncerraContribLote (FLGCOBRA=0 onde DATAFINAL=ULTMESPREPARO) (4415-4425)

Regras: CONTRIB-RN013 (ignora planos desativados), CONTRIB-RN014-020 (condições ULTMESPREPARO), CONTRIB-RN046 (mês anterior não processado)

Efeitos BD: INSERT HSTCONTRIBPREV, INSERT CTRLINTERFACE, UPDATE CONTRIBPREVPARTP.ULTMESPREPARO, UPDATE CONTRIBPREVPARTP.FLGCOBRA

EnviaContribuicaoCcp — FPreparaEnvia.pas:4510-5687

Propósito: Núcleo do envio. Envia contribuições preparadas para Folha (TMPDESC) ou Banco (CAR/CAP + contabilidade + alteradores).

Processamento:

  1. SELECT TIPOPERENVIO de PARAMAPREV (4576); verifica 13º nos lotes (4588-4617)
  2. Monta sSQLLotes: SELECT HSTCONTRIBPREV WHERE SITRECEBIMENTO IN ('0','8') GROUP BY IDLOTE (4684-4814)
  3. Para cada lote: LerContribAEnviar → loop qryEnvio (4974-5465)
  4. Se FLGDESCFOLHA=1 e FlgPagador='C' → EnviaContribuicao (folha); senão EnviaContribuicaoBANCO (4984-5045)
  5. UPDATE HSTCONTRIBPREV SET SITRECEBIMENTO=1, DATAEMISSCOB=SYSDATE (5193-5212)
  6. IncluiContabilidade; INSERT CONTABCONTFUND (5143-5181)
  7. DescarregaDocumentos + EnviaAlteradorBANCO por quebra de pessoa/data (5268-5452)
  8. Se CbBpd: UPDATE HSTCONTRIBPREV SET CODDOCUMENTOPREV=20, SITRECEBIMENTO=1 (5560-5582)
  9. RealizaIntegracaoPGAIndiv; CtrlBaixaRecXPag.ProcessaBaixaDocumento (5646-5653)

Regras: CONTRIB-RN055-070 (filtros de envio), CONTRIB-RN072 (BPD)

Efeitos BD: UPDATE HSTCONTRIBPREV.SITRECEBIMENTO, INSERT TMPDESC, INSERT DOCUMENTO/LANCTODOCUM, INSERT CONTABCONTFUND, UPDATE CTRLINTERFACE

Propósito: Calcula o valor da contribuição via regra e grava no histórico.

Parâmetros: psDataPrevista, sNomeContrib, psFlgInterno, psAnoMesReferencia: String; piQtdeContribAssoc: Integer; var pbC

Processamento: MontaSQLParaRegraCalculo ou MontaSQLAssoc → RegraNumerica → TestaPrimeiroPagto → GravaHistorico → AtualizaUltMesPREPARO

Regras: CONTRIB-RN007 (mês 13 usa SALPARTIC13), CONTRIB-RN032-036 (FLGTPVLR B/N/V), CONTRIB-RN052 (cobra 13º)

Efeitos BD: INSERT/UPDATE HSTCONTRIBPREV, UPDATE CONTRIBPREVPARTP.ULTMESPREPARO

GravaHistorico — FPreparaEnvia.pas:2611-2884

Propósito: Insere ou atualiza linha em HSTCONTRIBPREV.

Parâmetros: psAnoMesReferencia, psDataPrevista, sValEsperado, sFlgNaoExigeRec: String; iNumRecebimento, iNumParcela, iIdRegra, iIdPessoa, iIdPessJur, iIdPlanoPrev, iIdContribuicao: Integer; bTestarValor: boolean; var bValorZERO: boolean → boolean

Processamento: Converte valor; se <0 aborta; define SITRECEBIMENTO ('2' se FLGNAOEXIGEREC='1', senão '0'); INSERT ou UPDATE HSTCONTRIBPREV

Regras: CONTRIB-RN024 (valor negativo aborta), CONTRIB-RN025 (valor zero obrigatório), CONTRIB-RN026 (não exige recebimento)

bbtnDesfazerClick — FPreparaEnvia.pas:5897-6666

Propósito: Desfaz envio e/ou preparo de contribuições (coletivo ou individual por participantes selecionados).

Processamento: SELECT HSTCONTRIBPREV WHERE SITRECEBIMENTO<='1' → coleta documentos EMISBLOQ='S' (aborta) → loop por lote: DELETE TMPDESC, UPDATE/DELETE HSTCONTRIBPREV, DELETE HSTATRASOCONTRIB, DELETE HISTRUBSAL, DELETE CONTABCONTFUND, UPDATE CONTRIBPREVPARTP.ULTMESPREPARO, EstornaContribuicaoBANCO

Regras: CONTRIB-RN073 (mês 13→12), CONTRIB-RN074-080 (condições de desfazer), CONTRIB-RN077 (boleta enviada bloqueia)

Efeitos BD: DELETE TMPDESC, UPDATE/DELETE HSTCONTRIBPREV, DELETE HSTATRASOCONTRIB, DELETE HISTRUBSAL, DELETE CONTABCONTFUND, DELETE CTRLINTERFACE, UPDATE CONTRIBPREVPARTP

💡 Em outras palavras: PreparaContribuicao é o “cálculo do mês”: para cada patrocinadora, plano e situação do participante, aplica a fórmula de cada contribuição e grava o valor devido no livro-caixa. EnviaContribuicaoCcp é o “despacho”: pega o que foi preparado e ainda não enviado (situação 0 ou 8, FPreparaEnvia.pas:4712) COMPROVADO e manda para a folha ou para o banco. bbtnDesfazerClick é o “desfazer”: apaga o preparo/envio enquanto nada foi recebido.

👔 Para o analista de negócios

  • Regra de canal (folha × banco): a contribuição vai para desconto em folha quando o indicador de desconto em folha é 1 e o pagador é o próprio contribuinte (“C”), ou é a patrocinadora (“P”) com o indicador FLGRECECONTPATRO = 1. Nos demais casos, vira cobrança bancária (FPreparaEnvia.pas:4984-4999) COMPROVADO. O significado exato das letras “C”/“P” é INFERIDO.
  • Preparo em blocos: o preparo salva a cada 800 registros (FPreparaEnvia.pas:665, 4174-4180) e o envio também (FPreparaEnvia.pas:5456) COMPROVADO. Se o processo cair no meio, parte do mês já ficou gravada — a operação deve saber usar o “desfazer” antes de reprocessar.
  • Falha na integração com o PGA desfaz o envio: se a integração falhar, o sistema mostra “ERRO AO REALIZAR INTEGRAÇÃO COM O PGA” e executa Rollback (FPreparaEnvia.pas:5662-5663) COMPROVADO.

IncluiHSTCONTRIBPREV — FRecebeContribuicao.pas:2703-3004

Propósito: Insere registro em HSTCONTRIBPREV. Define SITRECEBIMENTO: 2 se esperado=recebido, 3 se dif>margin (VLRACEITADIVERG).

Além disso, esta tela não está no projeto (ContribuicaoPREV.dpr:128 inclui só FRecebeContribuicaoNovo), e o procedimento usado pela tela nova (SCRIPT/SIG33372/04_Script_SIG33372_DDL (Sp_Cp_Receb_Patro).txt) não menciona VLRACEITADIVERG. Confirmar se a tolerância de divergência ainda é aplicada no recebimento atual.

⚙️ FCalcSalContr.pas — Bitributação
bbtnConfirmarClick — FCalcSalContr.pas:440-781

Propósito: Núcleo do cálculo de bitributação.

Processamento: Para cada participante: DELETE HSTBITRIBUTACAO(OPERACAO='E') → busca DIP → Fase1: soma contribuições 1989-1995 corrigidas (moeda 557) → InserirHSTBITRIBUTACAO('E') → Fase2: saldo inicial 2007/12, itera IPCA-E (moeda 285) ≥2008/01: saldo = saldo × (COTVALOR/100 + 1), soma operação 'S' → InserirBITRIBUTACAO

Regras: CONTRIB-RN20 (flgativo se saldo>0 e DIP≥2013/01)

Efeitos BD: DELETE/INSERT HSTBITRIBUTACAO, INSERT/UPDATE BITRIBUTACAO

💡 Em outras palavras: esta rotina calcula a parte das contribuições que já foi tributada no passado, para que não seja tributada de novo no benefício. Ela soma as contribuições recebidas entre 01/01/1989 e 31/12/1995 (FCalcSalContr.pas:408) COMPROVADO, corrige esse valor e, a partir de 2008/01, atualiza pelo IPCA-E (moeda 285, conforme comentário em FCalcSalContr.pas:18-20) COMPROVADO. A ligação com a legislação de IR do período é INFERIDO.

👔 Para o analista de negócios

  • O resultado da bitributação afeta o imposto de renda do participante no momento do benefício ou resgate. Qualquer mudança de índice, período ou regra precisa de validação da área tributária/jurídica.
⚙️ FProvPerdasLote.pas / FProvPerdasIndiv.pas — Provisão para Perdas
Processa — FProvPerdasLote.pas:473-558 / ProcessaTodosSelecionados — FProvPerdasIndiv.pas:743-820

Propósito: Calcula e grava provisão para perdas de contribuições atrasadas.

Processamento: AbreQryContribuicao (SELECT HSTCONTRIBPREV WHERE MESCOBRANCA≠MESREFERENCIA, SITRECEBIMENTO IN (0,1), pai SITRECEBIMENTO=4) → loop: VALORPROV = (TOTALESPERADO/100) × PERCENTUAL (faixa de dias) → grava qryProvPerds → IncluiContabilidadeProvPerdas

Regras: CONTRIB-RN27 (filtros de contribuições atrasadas), CONTRIB-RN28 (seleção obrigatória)

Efeitos BD: INSERT PROVISAOPERDASCONTRIBUICAO, INSERT CONTABCONTFUND (contabilidade da provisão)

💡 Em outras palavras: a provisão para perdas é uma reserva contábil para contribuições que provavelmente não serão pagas. O valor provisionado é o total esperado multiplicado pelo percentual de uma faixa ((TOTALESPERADO / 100) × PERCENTUAL), e a faixa depende dos dias de atraso, contados da primeira data de inadimplência até hoje (FProvPerdasLote.pas:845-848, 905; FProvPerdasIndiv.pas:545-549, 605) COMPROVADO.

👔 Para o analista de negócios

  • As faixas e percentuais ficam na tabela FAIXASPROVISAOPERDACONTRIB (FProvPerdasLote.pas:857) COMPROVADO. Elas são um parâmetro contábil de negócio: quem altera, com que aprovação e com que periodicidade deve ser definido pela área contábil.
⚙️ FAtualizaPorIndice.pas — Atualização por Índice
bbtnEnviarClick — FAtualizaPorIndice.pas:421-957

Propósito: Atualiza reservas aplicando índice de correção mês a mês.

Processamento: valida data → SELECT RESERVAXPLANO (FLGMODATUALIZACAO=1) → para cada reserva: se tem regra → RegraNumerica mês a mês; senão itera índices: dValorAtualizado = dValorAtualizado × COTVALOR → InsereMovimentoReserva → UPDATE RESERVAPART.DATAULTATUALIZA

Regras: CONTRIB-RN42-45 (validações de seleção e participante)

Efeitos BD: INSERT HISTMOVRESERVA, UPDATE RESERVAPART.VALORRESERVA, UPDATE RESERVAPART.DATAULTATUALIZA

💡 Em outras palavras: esta rotina “corrige” as reservas dos participantes por um índice (ou por uma fórmula, quando existir), mês a mês, e grava cada movimento no extrato da reserva. O desfazer apaga as atualizações feitas até a data indicada, após confirmação do usuário (FAtualizaPorIndice.pas:989) COMPROVADO.

👔 Para o analista de negócios — síntese (PFC-42)

As rotinas mostram onde estão as regras com maior impacto financeiro:

  • Preparo/Envio (FPreparaEnvia): valor devido, canal de cobrança, contabilização e integração com PGA.
  • Recebimento: conferência esperado × recebido e tolerância de divergência — com ponto a validar sobre qual tela/procedimento está ativo.
  • Provisão para perdas: percentual por faixa de dias de atraso, parametrizado em tabela.
  • Bitributação: período 1989–1995 e índice IPCA-E desde 2008/01, com efeito no IR do participante.

Perguntas para levar ao responsável de negócio:

  1. A tolerância de divergência (VLRACEITADIVERG) ainda é uma regra vigente? Qual valor é usado por contribuição?
  2. Quem mantém as faixas de provisão para perdas e qual é a política contábil por trás delas?
  3. Em caso de falha no meio do preparo mensal, qual é o procedimento operacional padrão?
