📖 Para o leigo — Os relatórios que o sistema emite (enriquecido — PFC-42)

Esta aba lista os relatórios que o módulo CONTRIBUIÇÃO consegue gerar. São 16 relatórios em Relatorios/, cada um com uma tela de parâmetros e um DataModule que busca os dados.

Tipos de relatório mais comuns neste módulo:

  • Extrato de poupança — mostra o saldo acumulado do participante ao longo do tempo. É o relatório mais visível para o participante.
  • Extrato de desligamento — mostra os saldos finais quando o participante se desliga. Usado para acerto de contas.
  • Relatório financeiro de contribuições — lista as contribuições por patrocinadora, plano e período. Usado pela contabilidade.
  • Movimento de contribuições — detalha o envio e recebimento de contribuições por mês. Usado para conciliação.
  • Provisão constante / provisão para perdas — mostra os valores provisionados. Usado pela contabilidade e auditoria.
  • Consulta de eventos / histórico de reservas / log de operações — consultas operacionais para o dia a dia.

Atenção: 10 units de relatório são referenciadas no projeto mas não existem na pasta do módulo (estão marcadas como PENDENTE). Provavelmente são relatórios compartilhados ou removidos, mas isso não foi confirmado.

💼 Para o analista de negócios — Relatórios para tomada de decisão (enriquecido — PFC-42)

Relatórios de valor estratégico (usam-se para prestação de contas, auditoria e gestão):

  • Extrato de Poupança (FPRelExtPoup) — base para prestação de contas ao participante. É o relatório de maior visibilidade externa.
  • Extrato de Desligamento (FParamRelExtratoDeslig) — usado no acerto de contas quando o participante se desliga; erro aqui gera disputa.
  • Relatório Financeiro (FParamRelFinanc) — alimenta a contabilidade com os valores de contribuição; erro aqui gera inconsistência contábil.
  • Provisão para Perdas (dRelProvPerdas) — usado para o resultado contábil e para a análise de risco de crédito do fundo.
  • Log de Operações do TotalPREV (FConsLogTotalPREV) — auditoria de quem fez o quê e quando. Base para investigação de incidentes.

Risco de units ausentes: 10 units de relatório referenciadas no DPR mas não presentes na pasta. Impacto: se essas units forem necessárias em runtime, o módulo pode falhar ao acessar certos relatórios. Recomenda-se confirmar se foram removidas intencionalmente ou se são compartilhadas.

Recomendação: antes de qualquer mudança nos relatórios, validar com as áreas consumidoras (contabilidade, auditoria, participante) quais campos e formatos são esperados, pois mudanças podem quebrar integrações com sistemas externos (portal do participante, contabilidade).
