2. Descrição Resumida

O módulo BENEFICIOPREV (Benefício Previdenciário) é o componente do sistema CM Contabilidade / FUNCEF responsável pela concessão, manutenção e desfazimento de benefícios previdenciários, eventos geradores (aposentadoria, falecimento, reclusão, assistido), reajustes, conciliação INSS, desdobramento e controle de dívidas. O caso de uso organiza-se em 18 jornadas funcionais (JF001–JF018), mapeando 1:1 os 18 processos identificados no código-fonte (PF-01 a PF-18). Cada jornada possui objetivo, sequência operacional, ações práticas, regras de negócio (RS), tratamentos de erro (TRT) e mensagens (MSG). O motor de cálculo é externo (CMAdmPrev/UAdmPrev); o entry point é BeneficioPrev.dpr (Application.Title "Concessão e Manut de Benefícios Previdenciários"). Detalhamento de regras em 📏 Regras.

3. Pré-condições
  • O módulo BENEFICIOPREV deve estar compilado e disponível (entry point BENEFICIOPREV/Fontes/BeneficioPrev.dpr).
  • O banco Oracle (schema CM.) deve estar acessível.
  • Os módulos externos CMAdmPrev, CMPrevMT50 e CM Framework devem estar disponíveis.
  • Patrocinadoras, planos, participantes e benefícios devem estar cadastrados.
  • O usuário deve ter permissão de acesso ao módulo (IdModulo=454).
4. Pós-condições
  • As tabelas de benefício (BENEFBFCIARIO, HSTBENEFBFCIARIO, MOVBENEF, PROCESSOBENEF, HSTCONTRIBPREV, etc.) são populadas conforme a jornada executada.
  • Os eventos previdenciários são registrados em EVENTOSPREV com auditoria DATAALTERADO.
  • Toda operação de negócio é auditada em LOGTOTALPREV (IdModulo=454).
  • O isolamento por fundação (IDFUNDACAO) é mantido em toda SQL de negócio.

9. Observações Gerais (OBS)
  • OBS001: O módulo BENEFICIOPREV é um sistema desktop Delphi 5 / VCL, operado por usuário humano (diferente do UC097, que é backend puro).
  • OBS002: O motor de cálculo/concessão é externo (CMAdmPrev/UAdmPrev); o BENEFICIOPREV orquestra a UI e a persistência, delegando o cálculo ao motor.
  • OBS003: O arquivo com mais blocos try é FDesfazConcessaoBenefNOVO.pas (91 blocos), refletindo a complexidade do desfazimento por TIPOMOV (RS030).
  • OBS004: A evidência de cada regra é classificada como COMPROVADO (no código), INFERIDO (plausível) ou PENDENTE (validar). Esta classificação foi mantida do PFC-24.
  • OBS005: O menu de eventos é montado dinamicamente por FLGINTERNO (RS002), suportando TS/ID/IN/FL/RC/AI/BI.
  • OBS006: Os fluxogramas Mermaid representam somente comportamentos comprovados no código-fonte.
  • OBS007: O filtro de multi-fundação (IDFUNDACAO) está presente em quase toda SQL de negócio (RS045), garantindo isolamento de dados por fundação.
