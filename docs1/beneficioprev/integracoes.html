📖 Para o leigo — Como o módulo conversa com outros sistemas (enriquecido — PFC-42)

Esta aba mostra com quais outros sistemas o módulo BENEFICIOPREV conversa. Pense no módulo como uma pessoa no telefone: ele liga para vários "interlocutores" para conseguir fazer seu trabalho.

Com quem o BENEFICIOPREV precisa falar para conceder e manter benefícios:

  • CM Framework — a "biblioteca padrão" da suíte CM (20+ units). Fornece telas básicas, autorização, consultas e relatórios.
  • CMAdmPrev (8 units) — o motor de cálculo/concessão. É aqui que mora a inteligência de cálculo do benefício. O BENEFICIOPREV orquestra as telas, mas quem calcula é o CMAdmPrev.
  • CMPrevMT50 — DataModules de entidades previdenciárias centrais (planos, beneficiários).
  • UAdmPrev (40 refs) — regras de cálculo e concessão: PreparaBeneficioConcedido, VerificaVALORLimiteBeneficio, CalculaBeneficioAPagarNoMes etc.
  • UBeneficio (19 refs) — regras de benefício: CalculaBeneficioMinimo etc.
  • UParticipante (10 refs) — regras de participante.
  • UMovReserva (3 refs) — movimentação de reservas.
  • UIntegraBack — integração contábil/financeira (contabilidade, financeiro, plano de contas).
  • FOLHA / CONTRIBUIÇÃO — interface com a folha de benefícios e as contribuições. O BENEFICIOPREV fornece os beneficiários que o FOLHA paga.
  • Oracle — banco de dados (schema CM.). Onde tudo é gravado.
💼 Para o analista de negócios — Dependências críticas de negócio (enriquecido — PFC-42)

Dependências que podem parar a concessão (indisponibilidade aqui impede novas concessões):

  • CMAdmPrev (motor de cálculo) — sem o CMAdmPrev, não é possível conceder, manter ou simular benefícios. É a dependência mais crítica.
  • UAdmPrev (40 refs) — as regras de cálculo e concessão estão aqui. Sem estas regras, o benefício não pode ser calculado.
  • Oracle — sem banco, nenhuma operação é possível.
  • CMPrevMT50 — sem o cadastro de planos e beneficiários, a concessão não sabe para quem conceder nem em qual plano.

Dependências de saída (afetam a integração com sistemas externos):

  • UIntegraBack → contabilidade/financeiro — se a integração contábil falhar, o lançamento da concessão não é contabilizado.
  • FOLHA — o BENEFICIOPREV fornece os beneficiários que o FOLHA paga. Se o BENEFICIOPREV conceder/alterar/desfazer errado, o FOLHA pagará errado.

Acoplamento entre módulos: o BENEFICIOPREV, FOLHA e CONTRIBUIÇÃO são fortemente acoplados. O BENEFICIOPREV concede o benefício, a CONTRIBUIÇÃO calcula as contribuições que sustentam o benefício, e o FOLHA paga. Uma mudança em qualquer um dos três pode exigir re teste dos demais. Para uma eventual migração, considere os três como um bloco coeso.
