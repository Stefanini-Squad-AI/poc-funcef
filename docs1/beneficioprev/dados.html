📖 Para o leigo — Onde as informações ficam guardadas (enriquecido — PFC-42)

Esta aba descreve as "gavetas" onde o módulo BENEFICIOPREV guarda suas informações. No banco Oracle, cada gaveta é uma tabela com um nome.

As tabelas mais importantes para entender os benefícios:

  • BENEFBFCIARIO — o cadastro do beneficiário: quem é, qual o plano, qual o valor do benefício, quando começou (DIB), qual a situação (ativo, encerrado, suspenso). É a "ficha" de cada beneficiário (82 referências no código).
  • HSTBENEFBFCIARIO — o histórico do beneficiário: registra todas as alterações de valor, situação e lote. É o "diário" do benefício, para auditoria.
  • PROCESSOBENEF — o processo de benefício: cada benefício tem um número de processo, com situação e eventos associados.
  • MOVBENEF — o movimento do benefício: registra cada operação (concessão, retenção, encerramento, desdobramento, revisão) com data e tipo. É o "extrato" de operações.
  • EVENTOGERADOR — o catálogo de eventos geradores: aposentadoria (TS/ID), invalidez (IN), falecimento (FL), reclusão (RC), assistido (AI/BI). O menu de eventos é montado a partir desta tabela.
  • EVENTOSPREV — os eventos previdenciários registrados: cada evento disparado (ex.: falecimento do titular) é gravado aqui.
  • DETCONCINSS / CONCINSS — conciliação INSS: detalhe e cabeçalho da conciliação com mantenedoras.
  • CONTROLEDIVIDABENEFICIO — controle de dívida do benefício: usado no desdobramento (divisão do benefício entre herdeiros).

Ao todo são 25 entidades/tabelas centrais mapeadas. A tabela LOGTOTALPREV registra toda operação de negócio para auditoria (quem, quando, o que fez).

💼 Para o analista de negócios — Dados críticos para o negócio (enriquecido — PFC-42)

Dados de maior valor de negócio (perda ou inconsistência aqui tem impacto direto no benefício):

  • BENEFBFCIARIO.VALOR / DATACONCESSAO / DATAENCERRAMENTO — valor e período do benefício. Erros aqui geram pagamento indevido ou omissão.
  • BENEFBFCIARIO.IDSITBENEFICIO — situação do benefício (ativo, encerrado, suspenso). Erro aqui faz o benefício ser pago quando não deveria (ou vice-versa).
  • MOVBENEF.TIPOMOV — tipo de movimento (0=renovação, 3=retenção, 4=encerramento, 9=falecimento, 5=desdobramento etc.). O desfazimento usa este campo para saber qual operação desfazer.
  • PROCESSOBENEF.IDSITPROCESSO — situação do processo. Define se o processo está aberto, concedido, encerrado. Erro aqui bloqueia ou permite operações indevidas.

Integridade referencial crítica: BENEFBFCIARIO referencia PESSOA (titular), PATRO (patrocinadora), BENEFPLANPREV (plano), PROCESSOBENEF (processo), SITBENEFICIO (situação). Se qualquer desses cadastros for alterado/excluído, o benefício pode ficar inconsistente. O desfazimento existe para corrigir essas situações.

Auditoria (LOGTOTALPREV): toda operação de negócio (concessão, manutenção, desfazimento, evento) é registrada com data, usuário e descrição. É a fonte primária de rastreabilidade para auditoria interna e externa — relevante para conformidade e investigação de incidentes.

Impacto no pagamento: os dados deste módulo alimentam o FOLHA (módulo de pagamento). Se o benefício for concedido/alterado/desfeito errado aqui, o FOLHA pagará errado. A consistência entre BENEFICIOPREV e FOLHA é crítica.
