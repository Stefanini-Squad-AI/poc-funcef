📖 Para o leigo — O passo a passo dos processos (enriquecido — PFC-42)

Esta aba mostra o "passo a passo" dos principais processos do módulo BENEFICIOPREV, como uma receita ilustrada. Cada fluxo é um diagrama que mostra, em ordem, o que o sistema faz do início ao fim.

Os fluxos documentados (todos com rastreabilidade ao código):

  • PF-01 — Concessão de Benefício: usuário escolhe o tipo (Participante/Beneficiário/Pensionista) → o sistema chama o motor externo CMAdmPrev → o motor calcula o benefício → grava beneficiário, histórico, processo e movimento → registra auditoria.
  • PF-04 — Desfazer Operações: seleciona o processo → identifica a última operação → valida (já pago? prévia existe? folha efetivada?) → conforme o tipo de movimento, desfaz (renovação, retenção, encerramento, falecimento, desdobramento, liberação, revisão, reversão, alteração manual) → commit + auditoria.
  • PF-05 — Eventos Previdenciários: o menu é montado dinamicamente lendo EVENTOGERADOR → usuário escolhe o evento (aposentadoria, falecimento, reclusão, assistido) → o sistema grava o evento → atualiza elegibilidade → suspende contribuições.
  • PF-08 — Desdobramento: seleciona processo e beneficiários → valida (≥1 beneficiário, valor limite, motivo) → gera número de processo → calcula benefício/abono → reajusta desde DIP original → grava beneficiário, histórico, processo e dívida → commit + demonstrativo.
  • PF-14 — Conciliação INSS: importa arquivo do INSS/mantenedora → parser (header, detail, rubrica, footer) → grava conciliação e detalhe com rateio → importa mantenedora → identifica divergências → encerra conciliação (CR/CP + contábil).
  • PF-03 — Simulação: wizard de 4 etapas → seleciona participante → aplica regra de elegibilidade (data) → aplica regra de valor (numérica) → exibe resultado (apenas leitura).
  • PF-06 — Reajuste: carrega benefícios vitalícios não-resgate → exclui espécies específicas → importa lista de matrículas (Excel) → parametriza → grava reajuste → chama stored procedure.
💼 Para o analista de negócios — Gargalos e pontos de decisão (enriquecido — PFC-42)

Pontos de decisão de negócio (onde o sistema escolhe um caminho com impacto no benefício):

  • PF-01: tipo de benefício (P/B/D) — decide se a concessão é de participante, beneficiário ou pensionista. Erro aqui encaminha para o fluxo errado.
  • PF-04: TIPOMOV — o desfazimento decide qual operação desfazer conforme o tipo de movimento (0/7=renovação/concessão, 3/4=retenção/encerramento, 9=falecimento, 5=desdobramento, 12=liberação, 13/14=revisão, 16=reversão, 17=alteração manual). Erro aqui desfaz a operação errada.
  • PF-05: FLGINTERNO — decide qual form de evento abrir (TS=aposentadoria, FL=falecimento, RC=reclusão, IN/AI/BI=assistido). Eventos inativos (DO/AC/OE/RC) estão comentados.
  • PF-06: IDTPPAGTOBENEFIC=1 (vitalício) — só reajusta benefícios vitalícios não-resgate. Erro aqui reajusta benefícios indevidos.

Gargalos potenciais (pontos onde o volume pode impactar o tempo):

  • PF-06 (Reajuste) — importa lista de matrículas via Excel com validação e hash CRC32. Para grandes volumes, a importação pode ser lenta. Erros de importação (células vazias, formatos incorretos) podem gerar reajustes errados.
  • PF-14 (Conciliação INSS) — parser de arquivo do INSS linha a linha. Arquivos grandes podem levar tempo; falha no parser exige reimportação.

Dependências entre fluxos: PF-04 (desfazimento) só roda após PF-01 (concessão). PF-08 (desdobramento) depende de PF-01. PF-06 (reajuste) depende de PF-01. Uma falha na concessão bloqueia os fluxos subsequentes.
