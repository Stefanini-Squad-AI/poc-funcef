💡 Entenda esta página

O que esta página mostra: o tamanho funcional dos três módulos previdenciários (Folha de Benefícios, Contribuição Previdenciária e Benefício Previdenciário) medido em Pontos de Função (PF) pelo método IFPUG FPA (International Function Point Users Group — Function Point Analysis). O Pontos de Função é uma unidade de medida de software que conta o que o sistema faz para o usuário, não o tamanho do código.

Por que isso importa: o PF dá uma base objetiva e comparável para dimensionar o esforço de modernização, fazer benchmarking com outros sistemas e sustentar auditorias. Ao contrário de linhas de código, o PF mede a funcionalidade percebida pelo usuário — independente de ter sido escrito em Delphi 5, .NET ou qualquer outra tecnologia.

Como usar: clique num dos três cartões abaixo para abrir a análise do módulo. Cada análise tem inventário de funções de dados (ILF/EIF), funções transacionais (EI/EO/EQ), memória de cálculo, rastreabilidade e pendências. A página Metodologia da contagem explica os critérios e conceitos.

📜 Metodologia

A contagem segue o método IFPUG FPA (Análise de Pontos de Função do IFPUG). Os critérios de classificação, conceitos (EI/EO/EQ/ILF/EIF, DET/FTR/RET), tabelas de complexidade e tratamento de fronteiras estão em Metodologia da contagem.

Delphi 5 como contexto técnico, não fator de pontuação: o sistema foi desenvolvido em Delphi 5 (VCL, Oracle, MIDAS/DataSnap). Delphi 5 é registrado como característica técnica e ajuda a localizar implementações, mas não altera critérios de classificação nem a pontuação IFPUG. Não foram convertidas linhas de código, formulários, componentes ou rotinas Delphi em Pontos de Função.

⚠️ Premissas e limitações
  • Fronteira: cada módulo foi tratado como uma aplicação com fronteira própria. Os três módulos compartilham dados (BENEFBFCIARIO, HSTCONTRIBPREV, PREVIA, HISTRUBSAL) e têm integrações entre si — a análise de dupla contagem está na seção "Integrações e dependências" de cada módulo e na Metodologia.
  • Fonte primária: a documentação funcional de docs1/ (casos de uso, modelo de dados, integrações, regras de negócio). Código-fonte Delphi 5 é evidência auxiliar.
  • Pendências: funções cujos DETs/FTRs/RETs não puderam ser determinados com evidência são marcadas PENDENTE e não apresentadas como contagem confirmada.
  • Reproducibilidade: o total de PF de cada módulo é recalculado a partir do inventário na seção "Memória de cálculo".
