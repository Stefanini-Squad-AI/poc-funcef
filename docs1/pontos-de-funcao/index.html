🧮 Análise de Pontos de Função (IFPUG)

Tamanho funcional dos módulos Folha de Benefícios, Benefício Previdenciário e Contribuição Previdenciária — base para dimensionar a modernização.

🏠 Blueprint AS-IS 🧮 Pontos de Função 📐 Metodologia da contagem
💡 Entenda esta área

O que é: a Análise de Pontos de Função (APF) mede o tamanho funcional de um sistema — quanto de funcionalidade ele entrega ao usuário —, independentemente da linguagem em que foi escrito. Aqui ela foi aplicada, pelo método do IFPUG, aos três módulos previdenciários já documentados neste Blueprint.

Para que serve: dar uma base auditável para estimar o esforço de modernização, comparar com outros sistemas (benchmarking) e apoiar auditorias. Cada função contada tem tipo, justificativa e fonte; o total de cada módulo pode ser refeito a partir do seu inventário.

Como ler: escolha um módulo abaixo. Os critérios, conceitos e um exemplo passo a passo estão em Metodologia da contagem.

Atenção ao somar: cada módulo foi contado como uma aplicação separada INFERIDO. Tabelas compartilhadas (por exemplo BENEFBFCIARIO, HSTCONTRIBPREV, PREVIA, HISTRUBSAL) são contadas em cada módulo que as usa — como ILF onde são mantidas e como EIF onde só são lidas. Isso é correto para o tamanho de cada aplicação, mas a soma simples não é o tamanho de uma aplicação única: se o negócio decidir que os três módulos são uma só aplicação, as funções de dados compartilhadas seriam contadas uma única vez e os EIFs entre os módulos deixariam de existir. Ver a seção 7 de cada análise e a Metodologia.

A faixa das pendentes é apenas indicativa NÃO É CONTAGEM.

Cobertura: a contagem cobre as funcionalidades descritas nos casos de uso, jornadas e relatórios documentados. Os menus dos três módulos têm opções sem caso de uso documentado (listadas na seção 8.2 de cada análise); elas não foram contadas, pois não há descrição funcional que permita classificá-las. Por isso os totais tendem a subestimar o tamanho real até que essas opções sejam documentadas PENDENTE.
