Camadas de abstração (por que Abstractions 3.1)

Antes da linha 3.0, contratos compartilhados circulavam entre libs e geravam dependências circulares. FUNCEF.Abstractions centraliza interfaces que todas implementam:

  • ISecretReader / SecretRef — cofre e config
  • ICacheStore — Redis via NoSql (não IKeyValueStore legado)
  • ITelemetry, paginação — Essenciais e ORM consomem sem acoplar implementação
Regra prática: se você precisa de um contrato transversal, procure primeiro em Abstractions; se precisa de implementação, use a lib especializada (Cofre, NoSql, Essenciais).

Ordem de registro DI (backend)

Ordem importa para refresh token e resolução de segredos:

  1. Config + Key Vault (FUNCEF.Cofre)
  2. Redis cache (AddRedisCache — NoSql:RedisCache)
  3. ORM / persistência
  4. Autenticação + autorização (AddFUNCEFAuthentication, cliente GAP)
  5. Mediator, health, telemetria

Detalhe e troubleshooting: BE-05, BE-11.

Anti-padrões

  • Substituir Mediator por MediatR externo sem aprovação
  • AutoMapper quando [MapFrom] do ORM resolve
  • StackExchange.Redis direto — usar FUNCEF.NoSql
  • Mongo para auditoria — auditoria de entidade é Oracle Lakehouse; Mongo só document store
  • Axios ou fetch ad hoc no frontend — usar @/core/api
