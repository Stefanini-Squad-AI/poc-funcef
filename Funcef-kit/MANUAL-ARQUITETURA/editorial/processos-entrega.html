Processos de entrega

A FUNCEF adota Spec Driven Development (SDD): a especificação funcional define o comportamento; a Doutrina define como implementar; o código deve ser rastreável à spec.

Ciclo SDD FUNCEF

constitution (princípios Doutrina / CLAUDE.md)
    → specify (UCs, contratos, telas, state machines)
    → plan (decisões técnicas por marco)
    → tasks (T-NNN rastreáveis)
    → implement (BE / FE / BD)
    → validate → sync → archive (changes brownfield)

Detalhe: ADR-004 — Spec Driven Development.

Handshake spec → código

Artefato specO que o código deve refletir
UC (AG-13)Regras de negócio, Gherkin, fluxos principal/alternativo/exceção
Contrato (AG-16)Assinatura HTTP, DTOs, códigos de erro, validações
Screen (AG-15)Campos UI, ações, estados, permissões por campo
State machine (AG-17)Transições de status, guards, side effects
Tasks (AG-20)Itens T-NNN com agente roteado (be-*, fe-*, bd-*)
Regra: divergência spec ↔ doutrina é sinalizada e registrada — não improvisada. Código em sistema especificado deve citar UC-NNN, contrato ou T-NNN quando aplicável.

Evolução brownfield (change/delta)

Sistemas já em produção evoluem via change proposal:

  1. proposal.md — Why / What / Impact
  2. delta-spec.md — ADDED / MODIFIED / REMOVED sobre spec viva
  3. Implementação alinhada ao delta
  4. Sync funde delta em funcional/ e arquiva a change

Entrega de banco (DB-as-Code)

changeset Liquibase → PR → review (CODEOWNERS) → merge
    → pipeline DEV → HOM → MAIN (promoção controlada)
  • DDL/DML versionados; nunca editar changeset já aplicado — corrigir com novo changeset
  • SQL segue PadraoBD v2.2
  • PROD: IA/repositório só gera scripts; execução exige DBA/aprovação

LB-01 — Visão geral Liquibase

Definition of Done (fábrica)

Resumo do guia de onboarding — entrega aceita quando:

  • Conforme templates (web-template, api-template-base)
  • Build/testes/lint verdes (dotnet build, pnpm typecheck/lint/test:run)
  • Sem segredos commitados; Key Vault em HML/PRD
  • Contratos e UCs cobertos (Gherkin principal + alternativas + exceções)
  • DDL conforme PadraoBD quando aplicável

Detalhe: Guia onboarding fábrica §7.

Qualidade contínua

  • Doutrina viva — padrões evoluem com uso real; proposta antes de aplicar
  • Dual-write — capítulo Doutrina + agente/skill sincronizados
  • Validate-Pacote.ps1 — gate de consistência do pacote de agentes
