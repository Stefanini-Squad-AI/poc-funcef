04 — Walkthrough E2E (Task)

Nota **Objetivo**

Entregar um slice vertical completo: **criar e listar tarefas**. O FE de referência já existe em `web-template` (`features/tasks`); o BE e a tabela devem espelhar o mesmo contrato.

[!IMPORTANT]

**Não é slice pré-ligado**

O `web-template` traz `features/tasks` (mock em `:3001` no bootstrap). O `api-template-base` **não** expõe `/tasks` — só o domínio didático Clientes/Ordens. Este walkthrough é **exercício de implementação** (criar tabela + endpoints + apontar o BFF), não um pacote FE+BE já integrado.

[!CAUTION]

**Sem segredos**

Exemplos de HTTP usam `Authorization: Bearer ` como placeholder. Não cole tokens reais em PRs, chats ou este arquivo.

Contrato do slice

OperaçãoMétodoPath (API)Body
Listar`GET``/tasks`—
Criar`POST``/tasks``{ "title": "string" }`

**Modelo de leitura (JSON de negócio dentro do envelope):**

{
  "id": 1,
  "title": "Preparar kickoff",
  "done": false
}
```

**Envelope FUNCEF (forma típica):**

{
  "resultado": [ { "id": 1, "title": "Preparar kickoff", "done": false } ],
  "mensagem": "",
  "qtdRegistros": 1
}
```

No FE, após `createApi`, o hook lê `query.data?.data`.

Ajuste paths se o template BE usar prefixo `api/v1` — o BFF encaminha o sufixo após `/api/bff`. O importante é **FE `endpoints` = path relativo que a API expõe**.

Passo 1 — Tabela (Dados)

Ver [Playbook Dados](03-Playbook-Dados.md). Criar `.TB_TAREFAS` via Liquibase:

  • `TAREFA_ID` IDENTITY
  • `TITULO` VARCHAR2(200)
  • `FLAG_CONCLUIDO` NUMBER(1)
  • `DATA_CRIACAO` DATE

Passo 2 — Entidade e Application (Backend)

2.1 Entity

[Table("TB_TAREFAS", Schema = "{SCHEMA}")]
[Auditable("Tarefa")]
public class Tarefa
{
    [Key]
    [Column("TAREFA_ID")]
    [DatabaseGenerated(DatabaseGeneratedOption.Identity)]
    public long Id { get; set; }

    [Required, Column("TITULO"), MaxLength(200)]
    public string Titulo { get; set; } = string.Empty;

    [Required, Column("FLAG_CONCLUIDO", TypeName = "NUMBER(1)")]
    public bool Concluido { get; set; }

    [Required, Column("DATA_CRIACAO")]
    public DateTime DataCriacao { get; set; } = DateTime.UtcNow;
}
```

Registrar `DbSet` em `AppDbContext`.

2.2 DTOs alinhados ao FE

O FE usa `title` / `done` (inglês no contrato JSON do exemplo do template). Exponha JSON com essas propriedades (ou configure naming) para não quebrar o cliente:

public class TarefaCreateRequest
{
    public string Title { get; set; } = string.Empty;
}

public class TarefaResponse
{
    public long Id { get; set; }
    public string Title { get; set; } = string.Empty;
    public bool Done { get; set; }
}
```

No Service, mapear `Title` ↔ `Titulo`, `Done` ↔ `Concluido`.

2.3 Command Create + Query list

Siga o playbook Backend:

  1. `CreateTarefaCommand` + Validator (`Title` obrigatório, máx. 200) + Handler (`SaveChangesAsync`)
  2. `GetAllTarefasQuery` + Handler (lista → `List`)
  3. `ITarefaService` / `TarefaService` com `IRepository`
  4. Registrar service no DI

2.4 Controller

[ApiController]
[Route("tasks")] // ou "api/v1/tasks" — alinhar ao FE
[FuncefAuthorize]
public class TasksController : BaseController
{
    private readonly IMediator _mediator;

    [HttpGet]
    public Task<IActionResult> GetAll(CancellationToken ct)
        => ApiOk(_mediator.Receive(new GetAllTarefasQuery(), ct));

    [HttpPost]
    public Task<IActionResult> Create([FromBody] TarefaCreateRequest request, CancellationToken ct)
        => ApiCreated(_mediator.Send(new CreateTarefaCommand { Request = request }, ct));
}
```

2.5 Testes BE

  • Validator: título vazio → erro
  • Handler Create: mock de service/UoW ou teste de integração InMemory conforme padrão do template
  • `dotnet test` verde

Passo 3 — Smoke da API (local)

Com a API no ar (porta conforme template):

GET /tasks
Authorization: Bearer <ACCESS_TOKEN>
```
POST /tasks
Authorization: Bearer <ACCESS_TOKEN>
Content-Type: application/json

{ "title": "Primeira tarefa" }
```

Obter `` pelo fluxo Entra do kickoff — **não** versionar o token.

Passo 4 — Ligar o Frontend

O template já traz `features/tasks`. Ajustes:

  1. Em `.env.local`, `API_URL` aponta para a API real (dev) **ou** `http://localhost:3001` com `pnpm mock` enquanto o BE não estiver pronto.
  2. Confirme que `endpoints.ts` usa os mesmos paths do controller (`/tasks`).
  3. Tipos FE:
export interface Task {
  id: number;
  title: string;
  done: boolean;
}

export interface CreateTaskData {
  title: string;
}
```
  1. Rota autenticada `/tasks` + item de menu (ver `menu.config.ts` no template).
  2. `pnpm dev` — listar e criar tarefa via UI.

Fluxo de confiança: UI → `useAllTasks` / `useCreateTask` → `tasksApi` → `/api/bff/tasks` → API → Oracle.

Passo 5 — Teste FE (MSW)

Manter/ajustar handler MSW em `src/__tests__/msw/handlers.ts` para `GET/POST /tasks` (ou path BFF que os testes usam).

Rodar teste do hook (`use-tasks-query.test.tsx` no template) e `pnpm test:run`.

Passo 6 — Critérios de “slice pronto”

  • [ ] Changeset Liquibase aplicado em DEV
  • [ ] `GET/POST /tasks` na API com `[FuncefAuthorize]`
  • [ ] Envelope compatível com `createApi`
  • [ ] UI lista e cria tarefa autenticada
  • [ ] `dotnet test` + `pnpm typecheck && pnpm lint && pnpm test:run` verdes
  • [ ] Nenhum secret/token no Git
  • [ ] Demonstração no review (tela + request sem expor Bearer)

Passo 7 — Remover domínio didático do template BE

Quando Task (ou o domínio real) estiver estável, remova `Cliente`/`Ordem` do `api-template-base` conforme playbook Backend — evite dois domínios de exemplo em produção.
