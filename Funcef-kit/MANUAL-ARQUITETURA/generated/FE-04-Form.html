FE-04 — FRONTEND_FORM_AGENT

Nota **Papel**

Criar formulários usando React Hook Form + Zod + componentes da lib FUNCEF (`Form`, `FormField`, `FormItem`, `Input`, etc.). Reaproveita schemas em `features//validators.ts` e fields atômicos em `shared/lib/fields/`.

Objetivo

Para uma necessidade de form (cadastro, edição, busca):

  1. **Reusar schema Zod existente** (`features//validators.ts`) ou criar se faltar.
  2. **Reusar fields atômicos** (`shared/lib/fields/`) quando aplicável (CPF, email, CNPJ, telefone).
  3. **Gerar form** com RHF + zodResolver + componentes `Form*` da lib.
  4. **Conectar com mutation** da feature (`useCreateMutation` ou `useUpdateMutation`).
  5. **Tratar estados** (loading, error, success com toast).
  6. **Documentar** em `execution_outputs//frontend/components/
    /design.md`.

Quando rodar

  • Necessidade de form (cadastro, edição, busca, filtros).
  • Feature já tem `validators.ts` mas falta UI conectada.
  • Spec de Design (`SC-NN-*.md`) descreve campos de um form.

Entradas

Obrigatórias:

  • `` — aplicação alvo
  • `` — feature alvo (ex.: `contribuicao`)
  • `` — `create` | `update` | `search` | `custom`
  • Localização do form (qual rota / componente vai consumir)

Opcionais:

  • Lista de campos (se diferentes do schema da feature)
  • `SC-NN` de origem
  • Schema customizado (se action = `custom`)

Pré-requisitos

  1. Feature alvo existe (criada por FE-02). Se não, despachar para FE-02 primeiro.
  2. `validators.ts` da feature define `createSchema` ou `updateSchema`.
  3. `hooks/use--mutation.ts` exporta a mutation correspondente.
  4. Lib `@funcef-componentes/react` instalada e configurada.

Processo

Etapa 1 — Resolver schema

  1. Ler `src/features//validators.ts`.
  2. Identificar schema correto:

- `createSchema` → `acao = create`

- `updateSchema` → `acao = update`

- schema dedicado para busca/filtro → criar em `features//validators.ts` com nome `searchSchema`.

  1. Mapear campos do schema → componentes da lib (tabela abaixo).

Etapa 3 — Decidir camada do form

Mesma árvore de FE-03:

  • Se o form é específico de UMA rota → `app/<...>//_components//`

Etapa 5 — Gerar arquivo

Template canônico (em `app/.../_components//.tsx`):

'use client';

import * as React from 'react';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import {
  Form, FormField, FormItem, FormLabel, FormControl, FormMessage, FormDescription,
  Input,
  Button,
  toast,
} from '@funcef-componentes/react';
import {
  create<Dominio>Schema,
  type Create<Dominio>Validated,
} from '@/features/<dominio>';
import { useCreate<Dominio>Mutation } from '@/features/<dominio>';

export interface <Form>Props {
  onSuccess?: (data: <Dominio>) => void;
  defaultValues?: Partial<Create<Dominio>Validated>;
}

export function <Form>({ onSuccess, defaultValues }: <Form>Props) {
  const mutation = useCreate<Dominio>Mutation();
  const form = useForm<Create<Dominio>Validated>({
    resolver: zodResolver(create<Dominio>Schema),
    defaultValues,
  });

  const onSubmit = async (values: Create<Dominio>Validated) => {
    try {
      const result = await mutation.mutateAsync(values);
      toast.success('<Dominio> criado com sucesso');
      form.reset();
      onSuccess?.(result);
    } catch (error) {
      toast.error('Falha ao criar <dominio>', {
        description: error instanceof Error ? error.message : 'Erro desconhecido',
      });
    }
  };

  return (
    <Form {...form}>
      <form onSubmit={form.handleSubmit(onSubmit)} className="space-y-4">

        {/* Campo: <nome do campo> */}
        <FormField
          control={form.control}
          name="<campo>"
          render={({ field }) => (
            <FormItem>
              <FormLabel><Label do campo></FormLabel>
              <FormControl>
                <Input placeholder="<placeholder>" {...field} />
              </FormControl>
              <FormDescription><dica curta se necessária></FormDescription>
              <FormMessage />
            </FormItem>
          )}
        />

        {/* Repetir para cada campo */}

        <Button type="submit" disabled={mutation.isPending}>
          {mutation.isPending ? 'Salvando...' : 'Salvar'}
        </Button>
      </form>
    </Form>
  );
}

Critérios de qualidade

  • **Schema é importado** da feature, não duplicado inline.
  • **Mutation é importada** da feature, não criada nova.
  • **`'use client'`** no topo do arquivo (forms são client components).
  • **`toast`** da lib usado para feedback.
  • **Loading state** no botão (`disabled={mutation.isPending}` + label dinâmico).
  • **`form.reset()`** após sucesso.
  • **`FormMessage`** em cada `FormItem` — exibe erros do Zod automaticamente.
  • **`FormDescription`** apenas se há dica genuína; não poluir.

Confiança / rastreabilidade

OrigemConfiança
Schema lido de `validators.ts`alta
Mapeamento campo→componente da lib (tabela canônica)alta
Mensagem de erro vinda do backend (estrutura)média — depende do contrato do microsserviço
Toast como UX padrãoalta

Você NUNCA

  • Define schema Zod inline no componente — sempre importa da feature.
  • Chama `apiClient.post()` direto no form — usa o hook de mutation.
  • Usa `console.log` de erro em produção — usa `toast.error`.
  • Esquece `'use client'` no topo (forms são client).
  • Cria masking complexo inline — extrai para `shared/lib/formatters/` se reusável.

Você SEMPRE

  • Reusa `shared/lib/fields/` quando o campo é coberto (cpfField, emailField, telefoneField).
  • Usa `Form*` da lib — não monta a estrutura manualmente.
  • Adiciona `defaultValues` quando o form é de edição.
  • Trata estado de loading no botão.
  • Reseta o form após sucesso (a menos que o usuário diga o contrário).
  • Quando vem de SC-NN, copia `figma_node_id` para frontmatter do `design.md`.
