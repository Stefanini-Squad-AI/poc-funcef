BE-04 — Persistência e Transações

4.1 Modelo híbrido EF Core + Dapper

Microserviços FUNCEF usam EF Core e Dapper na mesma aplicação, ambos sob o componente FUNCEF.ORM:

TecnologiaQuando usarAcesso
**EF Core**CRUD padrão, navegações, change tracking, includes automáticos, transações multi-passo`IRepository` (genérico) ou navegando o `AppDbContext`
**Dapper**SQL específico Oracle, batch inserts, queries complexas com hints, operações de alta performance`IRepository.ExecuteAsync(sql, params, ct)`

Os dois compartilham:

  • A mesma connection (resolvida via FuncefORM)
  • O mesmo IUnitOfWork — BeginAsync/CommitAsync/RollbackAsync valem para ambos
  • O mesmo interceptor de auditoria (FuncefORM.Audit) — Dapper também é auditado quando FuncefORM:Audit:AuditDapperOperations = true

Decisão registrada em Decisoes-Arquiteturais ADR-006.

4.2 Contratos do FUNCEF.ORM

> Contratos-base transversais vivem em FUNCEF.Abstractions (CMP-08-Abstractions): a telemetria do BaseDbContext usa ITelemetry de Funcef.Abstractions.Telemetry e a paginação (PagedRequest/SortDirection) vem de Funcef.Abstractions.Pagination. O FUNCEF.ORM (CMP-02) referencia esses contratos.

TipoOrigemPapel
`BaseDbContext``FuncefORM.EFCore`DbContext base com interceptor de auditoria, telemetria, slow-query detection, resiliência Oracle
`IRepository``FuncefORM.Contracts`Repositório genérico: `AddAsync`, `UpdateAsync`, `DeleteAsync`, `GetByIdAsync`, `GetByIdWithAutoIncludesAsync`, `GetPagedAsync`, `ExistsAsync`, `GetFirstAsync`, `ExecuteAsync` (Dapper)
`IUnitOfWork``FuncefORM.Contracts``SaveChangesAsync`, `BeginAsync`, `CommitAsync`, `RollbackAsync`
`IUnitOfWork``FuncefORM.Contracts`Variante tipada por DbContext (uso interno)
`[Auditable("Recurso")]``FuncefORM.Audit.Attributes`Marca entidade para auditoria automática no `SaveChanges`
`[AutoInclude]``FuncefORM.Data.Attributes`Marca navegação para include automático em `GetByIdWithAutoIncludesAsync`
`[MapFrom("Prop")]` / `[NestedMap("Prop")]``FuncefORM.Mapping.Attributes`Mapeamento declarativo entidade → DTO sem AutoMapper
`MapTo(…)` / `MapToList()``FuncefORM.Mapping.Extensions`Métodos de extensão para executar o mapeamento

4.3 AppDbContext (padrão)

public class AppDbContext : BaseDbContext
{
    public DbSet<{Entidade1}> {Entidades1} { get; set; } = null!;
    public DbSet<{Entidade2}> {Entidades2} { get; set; } = null!;

    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        base.OnModelCreating(modelBuilder);

        modelBuilder.Entity<{Entidade1}>(entity =>
        {
            // Índice único filtrado (Oracle precisa do nome da coluna entre aspas duplas)
            entity.HasIndex(e => e.Email)
                .IsUnique()
                .HasFilter("\"EMAIL\" IS NOT NULL");
        });

        modelBuilder.Entity<{Entidade2}>(entity =>
        {
            entity.HasOne(e => e.{Entidade1})
                .WithMany(c => c.{Entidades2})
                .HasForeignKey(e => e.{Entidade1}Id)
                .OnDelete(DeleteBehavior.Restrict);
        });
    }
}
```

Padrão:

  • Mapeamento simples vive na entidade (Data Annotations [Table], [Column], [ForeignKey], [Index], [InverseProperty], [AutoInclude]).
  • Fluent API vive no DbContext — para configurações que não cabem em atributo:

- Índices únicos filtrados (Oracle: HasFilter("\"COLUMN\" IS NOT NULL") — coluna entre aspas duplas).

- OnDelete(DeleteBehavior.Restrict) para impedir deleção em cascata.

  • Chamar base.OnModelCreating é obrigatório (BaseDbContext aplica configurações globais).

4.4 Entidade — padrão

[Table("TB_{ENTIDADES}", Schema = "{SCHEMA}")]
[Auditable("{NomeRecurso}")]
public class {Entidade}
{
    [Key]
    [Column("{ENTIDADE}_ID")]
    [DatabaseGenerated(DatabaseGeneratedOption.Identity)]
    public long Id { get; set; }

    [Required, Column("NOME"), MaxLength(100)]
    public string Nome { get; set; } = string.Empty;

    [Column("EMAIL"), MaxLength(150), EmailAddress]
    public string? Email { get; set; }

    [Required, Column("DATA_CRIACAO")]
    public DateTime DataCriacao { get; set; } = DateTime.UtcNow;

    [InverseProperty(nameof({EntidadeRelacionada}.{Entidade})), AutoInclude]
    public ICollection<{EntidadeRelacionada}> {EntidadesRelacionadas} { get; set; }
        = new List<{EntidadeRelacionada}>();
}
```

Padrão de entidade dependente com FK (o nome da coluna FK é igual ao da PK referenciada):

[Table("TB_{ENTIDADES_DEPENDENTES}", Schema = "{SCHEMA}")]
[Auditable("{NomeRecurso}")]
[Index(nameof({Entidade}Id))]
[Index(nameof(Status))]
public class {EntidadeDependente}
{
    [Key]
    [Column("{ENTIDADE_DEPENDENTE}_ID")]
    [DatabaseGenerated(DatabaseGeneratedOption.Identity)]
    public long Id { get; set; }

    [Required, Column("{ENTIDADE}_ID")]
    public long {Entidade}Id { get; set; }

    [Required, Column("VALOR", TypeName = "NUMBER(10,2)"), Range(0.01, 99999999.99)]
    public decimal Valor { get; set; }

    [Required, Column("STATUS"), MaxLength(20)]
    public string Status { get; set; } = "Pendente";

    [Required, Column("FLAG_ATIVO", TypeName = "NUMBER(1)")]
    public bool Ativo { get; set; } = true;

    [ForeignKey(nameof({Entidade}Id)), AutoInclude]
    public {Entidade}? {Entidade} { get; set; }
}
```

Padrões obrigatórios:

PadrãoRazão
PK **própria por entidade** (sem `BaseEntity`): `[Key] [Column("{ENTIDADE}_ID")] [DatabaseGenerated(Identity)] long Id`Padrão FUNCEF/BancoDados: surrogate `NUMBER` com `IDENTITY`; coluna nomeada `{ENTIDADE}_ID` (não `ID` genérico), FK com o mesmo nome (ADR-014/015)
`[Table("TB_{ENTIDADES}", Schema = "{SCHEMA}")]`Prefixo `TB_` + **plural** (BD-02); schema explícito evita amarrar ao usuário Oracle default
`[Auditable("Recurso")]`Habilita auditoria automática no `SaveChanges`
Texto sem `TypeName` (`[Column("NOME")]` + `[MaxLength]`)Oracle `VARCHAR2` (BD-03); não usar `NVARCHAR2`
Data sem `TypeName` (`[Column("DATA_X")]`)Oracle `DATE`/`TIMESTAMP` default (BD-03)
`TypeName = "NUMBER(10,2)"`Decimais monetários — ajustar precisão conforme domínio
Boolean: `[Column("FLAG_X", TypeName = "NUMBER(1)")] bool`Oracle não tem BOOLEAN; `NUMBER(1) 0/1` mapeado nativamente pelo provider (ADR-017, BD-08). Conversor `'S'/'N'` só p/ coluna legada `CHAR(1)` (§4.4.1)
`[AutoInclude]` em navegação carregada-juntoPermite `GetByIdWithAutoIncludesAsync`
`[Index(nameof(Campo))]` em filtros frequentesPerformance Oracle

4.4.1 Boolean como NUMBER(1) (0/1) — ADR-017

Oracle não tem tipo BOOLEAN. Desde a ADR-017 (2026-07-08) o padrão é NUMBER(1) NOT NULL CHECK IN (0,1): a propriedade C# bool é mapeada nativamente pelo provider Oracle (true→1/false→0) — basta [Column("FLAG_X", TypeName = "NUMBER(1)")], sem conversor.

Legado CHAR(1) 'S'/'N' (ex.: api-ms-gap, forward-only): enquanto as colunas antigas não migram, registre o conversor apenas nessas propriedades (não globalmente, para não atingir as NUMBER(1) novas → ORA-01722):

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    base.OnModelCreating(modelBuilder);

    // SÓ para colunas legadas CHAR(1) 'S'/'N':
    modelBuilder.Entity<EntidadeLegada>()
        .Property(e => e.Ativo)
        .HasConversion(new BoolToStringConverter("N", "S"))
        .HasColumnType("CHAR(1)");
}
```

Colunas novas declaram TypeName = "NUMBER(1)". Ver doutrina BancoDados BD-08 §8.1 (representação de boolean).

4.6 Operações típicas via IRepository

public class {Entidade}Service : I{Entidade}Service
{
    private readonly IRepository<{Entidade}> _repository;
    private readonly IRepository<{EntidadeDependente}> _dependenteRepository;

    public virtual async Task<{Entidade}> CreateAsync({Entidade}Request request, CancellationToken ct = default)
    {
        if (!string.IsNullOrEmpty(request.Email)
            && await _repository.ExistsAsync(c => c.Email == request.Email, cancellationToken: ct))
            throw new ConflictException("{Entidade}", "Já existe um registro com este email");

        var entity = request.MapTo<{Entidade}Request, {Entidade}>(c =>
        {
            // Id NÃO é setado: PK IDENTITY gerada pelo banco no insert.
            c.DataCriacao = DateTime.UtcNow;
        });

        await _repository.AddAsync(entity, ct);
        return entity;
    }

    public virtual async Task<{Entidade}> UpdateAsync(long id, {Entidade}Request request, CancellationToken ct = default)
    {
        var entity = await _repository.GetByIdAsync(id, cancellationToken: ct)
            ?? throw NotFoundException.ForResource("{Entidade}", id);

        if (!string.IsNullOrEmpty(request.Email))
        {
            var dup = await _repository.GetFirstAsync(
                c => c.Email == request.Email && c.Id != id, cancellationToken: ct);
            if (dup != null) throw new ConflictException("{Entidade}", "Email já em uso por outro registro");
        }

        entity.Nome = request.Nome;
        entity.Email = request.Email;

        await _repository.UpdateAsync(entity, ct);
        return entity;
    }

    public virtual async Task ValidateAndDeleteAsync(long id, CancellationToken ct = default)
    {
        var entity = await _repository.GetByIdAsync(id, cancellationToken: ct)
            ?? throw NotFoundException.ForResource("{Entidade}", id);

        var temDependentes = await _dependenteRepository.ExistsAsync(
            d => d.{Entidade}Id == id, cancellationToken: ct);

        if (temDependentes)
            throw new ConflictException("{Entidade}", "Não é possível excluir registro com dependentes");

        await _repository.DeleteAsync(entity, ct);
    }
}
```

Padrões observáveis:

PadrãoPor quê
Métodos `virtual`Permite mock/override em testes e extensão por herança
Service nunca chama `SaveChangesAsync()`Quem decide quando persistir é o Handler
Validações de domínio antes da escritaFalha rápido com exceção tipada — sem corromper estado
`GetByIdAsync` retorna `null` para "não encontrado" no ServiceQuem traduz para HTTP 404 é o Handler (`?? throw NotFoundException.ForResource`) — exceto em UPDATE/DELETE onde o próprio Service já lança

4.7 IUnitOfWork — o ciclo de transação

MétodoQuando chamar
`SaveChangesAsync(ct)`Final de Handler simples (não há `Begin/Commit` quando só há uma chamada lógica)
`BeginAsync(ct)`Antes de iniciar transação explícita
`CommitAsync(ct)`Após todas as operações da transação terem dado certo
`RollbackAsync(ct)`Em qualquer falha — deve ser **safe** (try/catch interno)

Caso 1 — Transação implícita (1 SaveChanges)

public async Task<{Entidade}Response> Handle(Create{Entidade}Command command, CancellationToken ct)
{
    var entity = await _service.CreateAsync(command.Request, ct);
    await _unitOfWork.SaveChangesAsync(ct);
    return entity.MapTo<{Entidade}, {Entidade}Response>();
}
```

Caso 2 — Transação explícita EF Core (multi-Service)

await _unitOfWork.BeginAsync(ct);
try
{
    var entityA = await _serviceA.CreateAsync(requestA, ct);
    await _unitOfWork.SaveChangesAsync(ct);

    var entityB = await _serviceB.CreateAsync(requestB, ct);
    await _unitOfWork.SaveChangesAsync(ct);

    await _unitOfWork.CommitAsync(ct);
    return new {Resultado}Response { /* ... */ };
}
catch
{
    await SafeRollbackAsync(ct);
    throw;
}
```

Padrão SafeRollbackAsync — nunca deixar uma exceção de rollback mascarar a exceção original:

private async Task SafeRollbackAsync(CancellationToken ct)
{
    try
    {
        await _unitOfWork.RollbackAsync(ct);
        _telemetry.LogWarning("Rollback EF executado com sucesso");
    }
    catch (Exception rollbackEx)
    {
        _telemetry.LogError("Erro ao executar rollback EF", rollbackEx);
    }
}
```

Caso 3 — Transação explícita Dapper

var dataAtual = DateTime.UtcNow;

await _unitOfWork.BeginAsync(ct);
try
{
    // A PK é IDENTITY: o INSERT devolve o Id gerado (RETURNING ... INTO).
    long idA = await _serviceA.CreateWithDapperAsync(command.RequestA, dataAtual, ct);
    long idB = await _serviceB.CreateWithDapperAsync(idA, command.RequestB, dataAtual, ct);

    await _unitOfWork.CommitAsync(ct);
    return new {Resultado}Response { /* ... */ };
}
catch
{
    await SafeRollbackAsync(ct);
    throw;
}
```

Diferenças notáveis para Dapper:

  • PK gerada pelo banco (IDENTITY): o insert não informa a coluna da PK; o Id gerado volta via RETURNING {ENTIDADE}_ID INTO :Id (parâmetro de saída). Uma FK filha usa o Id devolvido pelo insert do pai.
  • Sem SaveChangesAsync entre operações — o SQL já foi executado; só falta Commit.

4.8 Service usando Dapper

public virtual async Task<long> CreateWithDapperAsync(
    {Entidade}Request request, DateTime dataAtual, CancellationToken ct = default)
{
    const string sql = @"
        INSERT INTO {SCHEMA}.TB_{ENTIDADES} (NOME, EMAIL, DATA_CRIACAO)
        VALUES (:Nome, :Email, :DataCriacao)
        RETURNING {ENTIDADE}_ID INTO :Id";

    var parameters = new DynamicParameters();
    parameters.Add("Nome", request.Nome, DbType.String);
    parameters.Add("Email", request.Email, DbType.String);
    parameters.Add("DataCriacao", dataAtual, DbType.DateTime);
    parameters.Add("Id", dbType: DbType.Int64, direction: ParameterDirection.Output);

    await _repository.ExecuteAsync(sql, parameters, ct);
    return parameters.Get<long>("Id");
}
```

Pontos críticos:

DetalhePor quê
Bind variable `:Nome` (não `@Nome`)Sintaxe Oracle (`@` é SQL Server)
INSERT **omite a PK** + `RETURNING {ENTIDADE}_ID INTO :Id`A PK é `IDENTITY`; o banco gera o valor e o devolve no parâmetro de saída (`long`)
Schema explícito `{SCHEMA}.TB_{ENTIDADES}`Boa prática para não depender do schema default da conexão
`_repository.ExecuteAsync`Usa a **mesma transação do `IUnitOfWork`** quando há `Begin` ativo

4.9 Mapeamento entidade → DTO

FuncefORM.Mapping substitui AutoMapper/Mapster. Configura-se uma vez no Infrastructure:

services.AddObjectMapper(options =>
{
    options.MaxDepth = 10;
    options.ThrowOnError = false;
});
```

DTO com atributos declarativos:

public class {Entidade}Response
{
    [MapFrom("Id")]              public long     Id          { get; set; }
    [MapFrom("Nome")]            public string   Nome        { get; set; } = string.Empty;
    [MapFrom("Email")]           public string?  Email       { get; set; }
    [MapFrom("DataCriacao")]     public DateTime DataCriacao { get; set; }
    [NestedMap("{Navegacao}")]   public List<{Navegacao}Resume>? {Navegacoes} { get; set; }
}
```
AtributoUso
`[MapFrom("Prop")]`Propriedade direta da entidade
`[NestedMap("Prop")]`Coleção ou objeto navegado (mapeia cada item recursivamente)

E na chamada:

var dto = entity.MapTo<{Entidade}, {Entidade}Response>();
var dtos = entities.MapToList<{Entidade}, {Entidade}Resume>();
```

Decisão registrada em Decisoes-Arquiteturais ADR-008.

4.10 Seeders (modo Dev)

public class {Entidade}Seeder : EntitySeederBase<{Entidade}>
{
    public override int Order => 1;

    public override IEnumerable<{Entidade}> GetSeedData()
    {
        yield return new {Entidade}
        {
            // Id NÃO é setado: a PK é IDENTITY e o banco gera o valor no insert.
            Nome = "Exemplo Seed",
            DataCriacao = DateTime.UtcNow
        };
        // ...
    }
}
```

Padrões:

  • Herda de EntitySeederBase (do FUNCEF.ORM).
  • Order define ordem de execução — pais com Order = 1, filhos com Order = 2.
  • Só rodam em Development (registro via AddFuncefORMDevelopment(assembly)).
  • PK IDENTITY não recebe valor no seed — o Id é gerado no insert. Para ligar filho→pai, use uma chave de negócio estável (código único) do pai já inserido para obter o Id gerado, em vez de fixar Ids. É assim que o api-ms-gap semeia entidades com FK sob identity.

4.12 Verificação de conectividade no startup (Dev/Hml)

Program.cs faz um CanConnectAsync antes de qualquer requisição em Dev/Hml — em Prd não roda (evita atrasar startup; o health /health/ready é quem sinaliza):

if (app.Environment.IsDevelopment() || app.Environment.IsEnvironment("Homologation"))
{
    using var scope = app.Services.CreateScope();
    var telemetry = scope.ServiceProvider.GetRequiredService<ITelemetry>();
    try
    {
        var context = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        if (await context.Database.CanConnectAsync())
            telemetry.LogInformation("Banco de dados conectado com sucesso");
        else
            telemetry.LogWarning("Banco de dados não está acessível. Verifique a connection string.");
    }
    catch (Exception ex)
    {
        telemetry.LogError(
            "Erro ao verificar banco de dados no startup. Configure KeyVault:Url ou FuncefORM:Connection:DirectConnectionString no appsettings.Development.json",
            ex, new Dictionary<string, object?> { ["message"] = ex.Message });
    }
}
```

4.13 Auditoria automática

MecanismoOndeO que faz
`[Auditable("{Recurso}")]` na entidade`Domain/Entities/{Entidade}.cs`Marca a entidade para auditoria
`services.AddFuncefOrmAudit(configuration)``Infrastructure/Extensions/ServiceCollectionExtensions.cs`Instala interceptor de `SaveChanges` que captura `Added/Modified/Deleted`
`FuncefORM:Audit:AuditDapperOperations: true``appsettings.json`Estende para operações Dapper (via `IRepository.ExecuteAsync`)
`FuncefORM:Audit:ConnectionSecretName: "AuditOracle"``appsettings.json`Auditoria pode ir para schema/banco separado
`GlobalIgnoredProperties``appsettings.json`Nunca audita `Password`, `Token`, `Secret`, etc.

A auditoria é gravada na tabela Oracle LOG_AUDIT.Registro_LOG. Detalhes do que é persistido (IP, UserAgent, CorrelationId, OldValues/NewValues) estão configurados em FuncefORM:Audit:* e o registro é feito pelo componente — não há código aplicacional para auditoria.

4.14 Boas práticas Oracle

Nota A nomenclatura de banco (schema, tabela, coluna, constraint, índice, tipos, boolean) é governada pela **doutrina BancoDados** (BD-02/03/04/08, ADR-014/015/016). A tabela abaixo resume o reflexo no EF Core; em caso de dúvida, o PadraoBD prevalece.

RecomendaçãoRazão
Schema UPPERCASE (`GAP`, `PEDIDOS`)Convenção Oracle e identificação rápida
Tabela `TB_` + **plural** UPPERCASE (`TB_PEDIDOS`)Convenção FUNCEF/BancoDados (BD-02)
PK surrogate `NUMBER` `IDENTITY`, coluna `{ENTIDADE}_ID`; FK com o mesmo nomeBD-04 / ADR-014/015 — sem `ID` genérico, sem `BaseEntity`
Coluna UPPERCASE `SNAKE_CASE` por extenso (`DATA_CRIACAO`; `NOME`/`DATA` sem abreviar)ADR-015 (`NM`/`DT` proibidos); compatibilidade com SQL puro
`DATE`/`TIMESTAMP` para datas (sem `TypeName` no EF, salvo precisão específica)Padrão BancoDados (BD-03)
`NUMBER(p,s)` para decimais monetáriosPrecisão exata
`VARCHAR2` para texto (sem `TypeName`; use `[MaxLength]`)Padrão BancoDados (BD-03); **não** usar `NVARCHAR2`
Boolean como `FLAG_ NUMBER(1)` mapeado `bool` nativo (ADR-017); conversor `'S'/'N'` **só** para coluna legada `CHAR(1)`, por-propriedadeOracle não tem BOOLEAN (BD-08) — ver §4.4.1
Índice em FK`[Index(nameof(EntidadeId))]`
`OnDelete(DeleteBehavior.Restrict)` em FKImpede orphan rows
Bind variables `:Param` em DapperSintaxe Oracle
INSERT Dapper omite a PK + `RETURNING {ENTIDADE}_ID INTO :Id`PK é `IDENTITY`; o banco gera e devolve o valor
