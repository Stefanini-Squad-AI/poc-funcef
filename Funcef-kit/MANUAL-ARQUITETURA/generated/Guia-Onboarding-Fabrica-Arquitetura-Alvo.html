Guia de Onboarding de Fábrica — Arquitetura Alvo FUNCEF

Importante **Público e propósito**

Documento para **fornecedor / fábrica de software** (anexo de RFP ou kickoff). Este arquivo é o **guia-mestre**: encaixa as peças e define Definition of Done. A implementação passo a passo está no pacote [`onboarding-fabrica/`](onboarding-fabrica/README.md).

Nota **Escopo**

Arquitetura alvo full-stack (FE · BE · dados). **Não** cobre legado, cutover, SLA comercial nem uso de ferramentas de IA.

[!CAUTION]

**Segredos e dados sensíveis**

Este pacote **nunca** contém tokens, senhas, connection strings, Client Secrets, Tenant IDs reais ou nomes internos de Key Vault/hosts. Use apenas placeholders. Credenciais e endpoints reais são entregues **somente** pelo canal seguro do kickoff FUNCEF.

3. Stack canônica (resumo)

Confirme versões nos templates no kickoff. Referência vigente (2026-08):

CamadaTecnologia
FENode ≥22 · pnpm · Next.js 16 · React 19 · TypeScript · Tailwind 4 · TanStack Query · RHF+Zod · `@funcef-componentes/react` **v3** · `@funcef-componentes/auth` **v3**
BE.NET 10 · C# 13 · Clean Arch 4 projetos · CQRS/Mediator (`FUNCEF.Essenciais`) · EF+Dapper (`FUNCEF.ORM`) · `FUNCEF.*` 3.x
DadosOracle 19c+ · Liquibase · PK `long` IDENTITY · `FLAG_*` NUMBER(1)
IdentidadeAzure Entra ID (OAuth2+PKCE web / Client Credentials M2M)
SecretsAzure Key Vault (valores **fora** deste documento)

**Proibido sem ADR:** Axios/`fetch` ad hoc no FE · `service.ts` no FE · MediatR/AutoMapper/Serilog/Newtonsoft de terceiros · provider ≠ Oracle · `middleware.ts` (usar `src/proxy.ts`) · npm/yarn no FE.

Detalhe: playbooks + [Stack-Canonica-Nucleo](Stack-Canonica-Nucleo.md).

3.1 Matriz de autenticação (FE × API)

CenárioLoginRedirect / sessionPapel do CORS na API
**Full BA (padrão fábrica)**Better Auth no Next (`@funcef-componentes/auth`)`/api/auth/*`, cookie no FEDados via BFF server-side (`/api/bff` → `API_URL`) — CORS browser→API **não** é o caminho principal
**Demo API wwwroot**`FUNCEF.Autenticacao` no API`Auth:EntraId:RedirectUri` (ex. `https://localhost:56055/auth/callback`)`Cors:Politica` / `Cors:OriginsPermitidas` importam para o browser no API

Não registre o RedirectUri do **API wwwroot** no App Registration quando o produto for Full BA (login no Next).

4. Visão full-stack e fluxo de confiança

sequenceDiagram
  participant Browser
  participant NextBFF as NextBFF_api_bff
  participant Auth as FuncefAuth_Entra
  participant API as ApiMicroservice
  participant DB as Oracle

  Browser->>NextBFF: same-origin /api/bff
  NextBFF->>Auth: resolve Bearer server-side
  NextBFF->>API: Authorization Bearer
  API->>DB: EF_or_Dapper
  API-->>NextBFF: envelope resultado
  NextBFF-->>Browser: ApiResponse normalizado
```
  1. Bearer Microsoft **não** circula em JavaScript do browser.
  2. Cliente chama só `/api/bff/*`.
  3. `API_URL` é variável **somente servidor**.
  4. API aplica authZ (`[FuncefAuthorize]` / GAP quando aplicável).
  5. Envelope FUNCEF normalizado pela lib FE (`createApi`).

7. Qualidade e Definition of Done

7.1 Anti-padrões (rejeitar)

**FE:** import cross-feature · `service.ts` · HTTP fora de `@/core/api` · Bearer no client · UI em inglês / código em PT · `middleware.ts` · MSW misturado com json-server · query keys inline.

**BE:** Application → Infrastructure · regra no controller · libs proibidas · PK Guid/`BaseEntity` sem ADR · engolir exceções tipadas · endpoint sem `[FuncefAuthorize]` (quando aplicável) · secrets commitados.

**Dados:** DDL direto em Hml/Prd sem Liquibase · renomear legado sem governança · `BOOLEAN` Oracle.

7.2 DoD de incremento

  • [ ] Comportamento coberto pela spec do incremento
  • [ ] FE: `pnpm typecheck && pnpm lint && pnpm test:run && pnpm build`
  • [ ] BE: `dotnet build` + testes verdes
  • [ ] Schema: changeset Liquibase (se houver mudança)
  • [ ] Rastreabilidade UC/contrato → código
  • [ ] Sem segredos no diff · Conventional Commits
  • [ ] Slice E2E do walkthrough (ou equivalente de domínio) demonstrável

8. Kickoff — acessos (sem segredos)

Solicitar à FUNCEF (valores **fora** deste doc):

  • [ ] Clone dos templates (`web-template`, `api-template-base`, repo DB-as-Code se houver)
  • [ ] Acesso ao feed NuGet `FUNCEF.*`
  • [ ] App Registration Entra (dev) — Client ID / secret / tenant / audience via canal seguro
  • [ ] Leitura Key Vault e schema Oracle DEV (nomes e secrets no kickoff)
  • [ ] Cenário de auth FE: **Full BA** (default) ou Consumidor TKF2
  • [ ] Pacote de especificação to-be do produto (se existir)

**Critério de onboarding completo:** ambientes locais sobem sem atalho que viole BFF/auth; existe um slice Task (ou domínio real) FE+BE; gates verdes; time alinhado aos anti-padrões.
```
