CMP-00 — Componentes FUNCEF.* (índice)

Nota **Propósito**

Catálogo orientativo das bibliotecas mantidas em `funcef-componentes/`. Cada `CMP-NN-*.md` resume **propósito**, **quando usar**, **principais extension methods**, **configuração mínima**, **snippets** e **anti-padrões**. Para detalhes profundos, consulte o `README.md` da lib correspondente (link no final de cada CMP).

[!NOTE]

**Stack linha 3.0 (3.0.0)**

As libs runtime FUNCEF.* estão em **3.0.0** (exceto **FUNCEF.Abstractions 3.1.0**), publicadas no GitHub Packages (pin canônico `[3.0.0,4.0.0)`). A linha inclui duas libs-base — **FUNCEF.Abstractions** ([CMP-08-Abstractions](./CMP-08-Abstractions.md), contratos-base) e **FUNCEF.Build** ([CMP-09-Build](./CMP-09-Build.md), build-time) — e o fim das dependências circulares: os contratos compartilhados (`ITelemetry`, `ISecretReader`, `ICacheStore`, paginação, health, identidade) agora vivem em **Abstractions**, e as demais libs apenas os implementam.

Quando consultar este índice

  • Quando o pedido envolver chamar um `Add{Servico}*` ou usar uma interface `FUNCEF.*` sem certeza do contrato.
  • Antes de gerar `Program.cs` ou `Infrastructure/Extensions/ServiceCollectionExtensions.cs`.
  • Quando o usuário perguntar "que lib faz X?" ou "como configuro Y?".
  • Para validar que um pacote externo (AutoMapper, Polly, etc.) não tem equivalente FUNCEF antes de propor.

`Abstractions` é o **piso de contratos** (zero dependências externas) — todas dependem dele, eliminando os ciclos que existiam antes de `Abstractions`. `Essenciais` é a base de implementação. `Cofre` é referenciada por quase todas (Key Vault). `ORM` está no topo da cadeia. `Build` não aparece no grafo de runtime: é build-time (`PrivateAssets="all"`).

Como cada CMP-NN está estruturado

Cada documento segue o mesmo esqueleto (~150-250 linhas, padrão Anthropic SKILL.md para progressive disclosure):

  1. **Frontmatter** com `id`, `lib_path`, `version`, `tags`, `related`.
  2. **Propósito** — 1 parágrafo.
  3. **Quando usar / Quando NÃO usar**.
  4. **Instalação NuGet**.
  5. **Principais extension methods** (`AddXxx`) e contratos (`IXxxService`, `IXxxStore`).
  6. **Configuração mínima** (`appsettings.json`).
  7. **Snippets** representativos (3-5).
  8. **Anti-padrões** específicos da lib.
  9. **Onde aprofundar** — link para `funcef-componentes//README.md`.

Política de uso (válida para todas as libs)

  1. **Toda dependência é registrada via `Add{Lib}*` no `Infrastructure/Extensions/ServiceCollectionExtensions.cs`**, nunca em controllers ou handlers.
  2. **Segredos resolvidos via Key Vault** (`FUNCEF.Cofre`) — não commitar credenciais.
  3. **Versões alinhadas no mesmo major (3.x)** — atualizar uma lib geralmente força atualizar as outras.
  4. **Contratos compartilhados vêm de `FUNCEF.Abstractions`** — ao injetar `ITelemetry`, `ISecretReader`, `IKeyValueStore` ou paginação, o `using` é `Funcef.Abstractions.*`, não o namespace da lib que implementa.
  5. **Não substituir** por equivalentes externos (AutoMapper, Polly, MediatR, Serilog standalone) — vide [Principios](../_shared/Principios.md) §2.
  6. **Quando há feature do `FUNCEF.*` para o caso de uso, usá-la** mesmo que pareça verbosa. Inconsistência entre microserviços é caro.
