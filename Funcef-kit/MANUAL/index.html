1. Comece aqui

Este kit permite desenvolver e entregar sistemas na arquitetura FUNCEF sem acesso ao Git interno nem aos feeds privados (GitHub Packages / npm privado).

O que você tem: templates em código-fonte, pacotes NuGet FUNCEF.* (.NET 10), pacotes npm @funcef-componentes/*, e este manual.

Pré-requisitos

  • .NET SDK 10
  • Node.js ≥ 22 e pnpm
  • Rede para nuget.org e registry.npmjs.org (dependências públicas)

Feeds locais

feeds/
  nuget.config          # funcef-local + nuget.org
  nuget-local/*.nupkg   # FUNCEF.*
  npm-local/*.tgz       # @funcef-componentes/*
  .npmrc.example

Backend: copie feeds/nuget.config para a raiz de templates/api-template-base e ajuste o caminho ./nuget-local se necessário (relativo à pasta do config).

cd templates/api-template-base
# exemplo: nuget.config apontando para ../../feeds/nuget-local
dotnet restore
dotnet build

2. Arquitetura FUNCEF em 15 minutos

  • Backend: .NET 10, Clean Architecture (API / Application / Domain / Infrastructure), CQRS via Mediator (FUNCEF.Essenciais), Oracle via FUNCEF.ORM, autenticação Entra + autorização PDP via FUNCEF.Autenticacao.
  • Frontend: Next.js + React, 4 camadas (app / features / core / shared), Design System @funcef-componentes/react, auth @funcef-componentes/auth, dados via BFF /api/bff (não chamar a API direto do browser no padrão Full BA).
  • Dados: Oracle 19c+, PadraoBD v2.2; cache Redis; Mongo opcional só como document store (não auditoria).
  • Segredos: Azure Key Vault; forma canônica *FromKeyVault: { Enabled, SecretName }. Nunca versionar segredos.

5. Usando os templates

api-template-base

  1. Copie a pasta, configure nuget.config → feed local.
  2. dotnet restore && dotnet build.
  3. Substitua o domínio didático (Cliente/Ordem) pelo domínio real (PK long IDENTITY).
  4. Preencha Entra / Key Vault com valores do kickoff (nunca commitados).

lib-api-template (funcef-api)

Scaffold CLI. Com o template instalado a partir desta fonte, gere novos microsserviços. Mesma stack e seções de config do api-template-base.

web-template

  1. Instale os .tgz do kit.
  2. Configure env do kickoff (TENANT_ID, CLIENT_ID, API_URL, etc. como placeholders).
  3. Use features/ como contrato de domínio; HTTP só via @/core/api → BFF.

6. Configuração e ambientes

AmbienteNotas
Developmentuser-secrets / connection strings locais aceitáveis; Swagger ON; refresh InMemory ok
Homologation / ProductionKey Vault obrigatório; refresh Redis; CORS com origens explícitas (Politica / OriginsPermitidas)

Proibido no Git: ClientSecret, connection strings, signing keys. Use placeholders <TENANT_ID>, <CLIENT_ID>, <KEY_VAULT_URL>, <SENHA>.

7. Troubleshooting

SintomaCausa provávelAção
Restore não acha FUNCEF.*nuget.config sem funcef-localVerificar path e packageSourceMapping
NU1603 / NU1109 em AbstractionsRange CPM sem o lower-bound no feedUsar pins exatos do kit (Directory.Packages.props)
Cache Redis “não liga”Seção NoSql:Redis antigaUsar NoSql:RedisCache
401 Entra (audience)aud vs ClientId / api://Alinhar ao token v2 (GUID) conforme kickoff
Refresh token não compartilha entre réplicasRedis depois do auth / StorageType erradoRegistrar AddRedisCache antes de auth; StorageType=Redis
