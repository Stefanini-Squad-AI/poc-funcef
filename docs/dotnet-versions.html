Relação com o Web Empréstimo

  • As duas aplicações tratam do mesmo negócio e usam o mesmo banco Oracle (schema CM). O Web Empréstimo lê e grava tabelas que o EMPRESTIMO Delphi 5 também usa, como CONTRATOEMPTMO, HISTMOVEMPTMO e PARAMEMPTMO, e chama a package CM.PCK_EMPRESTIMO (listada também na página do módulo Delphi).
  • Não há referência de código entre elas: o Web Empréstimo não usa units nem BPLs Delphi, e o Delphi 5 não chama os serviços WCF do Web Empréstimo. A integração é pelo banco.
  • Consequência para versões: a atualização do .NET Framework do Web Empréstimo não exige mudança no Delphi 5, e vice-versa. O que afeta as duas é mudança de estrutura no Oracle (tabelas, procedures, packages) e a versão do servidor Oracle, que precisa continuar compatível com o cliente nativo usado pelo BDE e com o Oracle.ManagedDataAccess 21.x do Web.

🧩 Análise de Migração Funcional — Delphi 5 × .NET 4.8
Estratégia do projeto (regra governante): o FUNCEF.WebEmprestimo em .NET Framework 4.8 é a base da nova aplicação. Tudo o que já estiver implementado nele deve ser aproveitado e apenas modernizado para .NET 10 + React 19. Somente as funcionalidades do módulo Delphi EMPRESTIMO com lacuna funcional comprovada em relação ao .NET 4.8 entram como migração funcional do Delphi. O esforço de modernização do WebEmprestimo e o esforço de migração de funcionalidades exclusivas do Delphi são contados separadamente, sem misturar.

O enunciado do card cita Funcef/EMPRESTIMO. No repositório, o módulo Delphi está em EMPRESTIMO/. A pasta FUNCEF/ é outra aplicação Delphi, e FUNCEF.WebEmprestimo/ é a aplicação .NET. Esta análise usa os caminhos reais do repositório.

Convenção de caminhos: caminhos Delphi são relativos à raiz do repositório (EMPRESTIMO/…, EMPRESTIMOBPL/…). Caminhos .NET são relativos a FUNCEF.WebEmprestimo/. Todos os caminhos citados foram conferidos no repositório.
