1. Resumo Executivo
  • Objetivo: migrar o módulo Contábil (Contab.exe) de Delphi 5 para backend C# (ASP.NET Core / API REST) e frontend React, preservando comportamento.
  • Escopo: CONTAB (+ CMCONTABOBJ50), reports, integrações de entrada/saída e dependências com CapCar, Orçamento, CAF, Folha e demais módulos que geram/consultam contabilidade.
  • Situação atual: aplicativo VCL maduro, ~113 forms MT, 46 tabelas DbObject, 55 units de relatório, arquitetura Ctrl/DbObject + MIDAS.
  • Tecnologia atual: Delphi 5 / VCL / MIDAS / DBTables-BDE / ReportBuilder / Oracle.
  • Tecnologia alvo: C# + ASP.NET Core (API REST, serviços de domínio, EF Core quando aplicável) + React (telas equivalentes).
  • Principais riscos: regras em Controllers extensos (uCtrlLancamento), SQL embutido, layouts regulatórios SIPC, integrações por arquivo sem especificação externa no repo, saldos/fechamento.
  • Principais dependências: GLOBALCM/CM framework, tabelas compartilhadas, CapCar, Orçamento, CAF, Folha/SRH, Excel/SAF/Fidélio/Posadas.
  • Pontos de atenção: preservação de partidas dobradas, bloqueio de período, segregação previdenciária, multi-moeda (PARAMCONTAB).

9. Interface React

A interface de destino é um SPA React que substitui as forms VCL do Contábil. O servidor permanece C# / ASP.NET Core: as telas não reimplementam regras de negócio (partida dobrada, saldos, bloqueio de período, rateio, segregação); consomem as APIs já catalogadas na seção 8 e em api-catalog.html.

  • Rotas: React Router, um caminho por form equivalente (tabela abaixo).
  • Páginas: componentes de função (JSX) que orquestram grids, filtros, wizards e upload.
  • Cliente HTTP: chamadas REST autenticadas às APIs C# (/api/contab/…); erros de negócio da API devem ser exibidos como no legado.
  • Estado de tela: formulários e listas no cliente; persistência e processamento apenas no backend C#.
